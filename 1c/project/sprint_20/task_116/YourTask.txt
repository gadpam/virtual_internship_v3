ЗАДАНИЕ task_116 · спринт 20 · Q2
Тема спринта: Отраслевые и государственные обмены: ЭДО, маркировка, кассы, банк
Маркировка и прослеживаемость: коды, агрегаты, выбытие

Оценка времени: 4 ч
Уровень задания: ядро — обязательное; без него спринт не закрыт

ЛЕГЕНДА И КОНТЕКСТ: ситуация и зачем это нужно
Государство требует прослеживать маркированные товары: каждая единица
с кодом — от приёмки до выбытия. Количественный учёт «100 штук» больше
не отвечает на вопрос «какие именно». Сегодня модель учёта получает коды.

Маркировка товаров добавляет измерение: каждая единица (или агрегат)
имеет код, который проходит путь от приёмки до продажи. Это меняет модель данных:
нужен учёт по кодам, а не только по количеству.

ТЕОРИЯ: что нужно знать перед выполнением
Код маркировки — уникальный идентификатор единицы товара (или
агрегата-упаковки, содержащего единицы). РС «КодыМаркировки» хранит:
код, номенклатуру, статус (принят/в наличии/выбыл/возвращён), документ-
источник, дату. Учёт по количеству и по кодам — два разреза одного
склада; главный инвариант: сумма по кодам в наличии = количество
товара на остатках, расхождение — инцидент (отчёт из задания).

Статусы кода — конечный автомат: нарисованная state machine задаёт
разрешённые переходы (принят → перемещён → выбыл; выбывший код нельзя
продать повторно). Запрет невозможных переходов ставится в одном месте
обработки кодов, а не проверками по всем документам.

Агрегаты: код упаковки раскрывается в коды единиц при приёмке/
перемещении; движение родителя двигает детей одним действием.
События выбытия (продажа, списание, возврат) меняют статус и пишут
источник — по коду восстанавливается вся его биография.

Данные маркировки объёмны (код на единицу товара): проектируют
сразу с прицелом на объёмы чеков из task_117.

Инвариант проверяется запросом: количество товара на остатках склада
минус коды в статусе «в наличии» = 0; намеренно сломав один статус,
отчёт расхождения обязан показать товар. Типичные ошибки: переходы
статусов проверять в каждом документе по-своему (один забыл — код
продался дважды); агрегат двигать, не раскрывая детей; коды хранить
строкой «через запятую» в документе вместо регистра.

Проверка понимания: кассир продал товар, код которого уже выбыл
возвратом. Какой механизм в вашей модели обязан это запретить
и в каком единственном месте он реализован?

Маркировка живёт тройками «введён — в обороте — выбыл»: код,
которого нет в учёте, или учёт без кода — расхождение, находимое
сверкой до проверки извне. Агрегаты (короб, палета) обязывают
поддерживать иерархию: выбытие агрегата без выбытия содержимого
по правилам — ошибка, которую система обязана ловить при сканировании.
Коды — создаваемый регистр задания (КодыМаркировки), объёмы кодов
считаются заранее: миллион кодов — это таблица, индексы и архив
(task_215), а не «строковое поле». Ошибки сканирования на кассе —
сценарий task_256 в мобильном контуре.

ЗАДАНИЕ: что сделать
1. Спроектируйте учёт кодов маркировки: РС «КодыМаркировки» (код, номенклатура,
   статус, документ-источник, дата). Модель и диаграмму состояний кода
   сохраните в internship/documentation/architecture/marking_model.md.
2. Реализуйте приёмку с кодами: проверка уникальности, статусов, принадлежности товару.
3. Реализуйте перемещение и выбытие кодов (продажа, списание, возврат).
4. Добавьте отчёт «Движение кодов» и отчёт о расхождениях между количеством и кодами.
5. Обработайте агрегаты: код упаковки содержит коды единиц.

РЕЗУЛЬТАТ (Definition of Done):
- Модель учёта кодов реализована и описана
- Приёмка/перемещение/выбытие работают и меняют статусы
- Отчёты формируются и находят искусственное расхождение
- Агрегаты обрабатываются (раскрытие упаковки)

ПОДСКАЗКИ МЕНТОРА:
- Проверяйте инвариант: сумма количеств по кодам = количество по документу. Это ваш главный контроль целостности.
- Статусы кода — это state machine. Нарисуйте её и проверьте все переходы, включая невозможные (продажа уже выбывшего кода).
