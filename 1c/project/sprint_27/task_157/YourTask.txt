Тема спринта: Отчётность бухгалтера и интеграция с 1С:Бухгалтерия
Оборотно-сальдовая ведомость на СКД

Оценка времени: 3 ч
Уровень задания: ядро — обязательное; без него спринт не закрыт

ЛЕГЕНДА И КОНТЕКСТ: ситуация и зачем это нужно
Оборотно-сальдовая ведомость — первый отчёт, который бухгалтер просит
и по которому разработчика судят. Сегодня ОСВ строится на виртуальных
таблицах регистра бухгалтерии средствами СКД — навык с любого
собеседования по 1С.

ОСВ — главный бухгалтерский отчёт: сальдо на начало, обороты за период,
сальдо на конец, в разрезе счетов и субконто. Сделать её на СКД — обязательный навык,
который проверяют на любом собеседовании по 1С.

ТЕОРИЯ: что нужно знать перед выполнением
ОСВ показывает по каждому счёту: сальдо на начало периода, обороты
Дт/Кт за период, сальдо на конец. Источник — виртуальные таблицы
регистра бухгалтерии: остатки берутся его таблицами на границы
периода, обороты — таблицей оборотов; считать «остаток на начало»
вручную из движений — запрещённый приём, для этого механизм и существует.

Признак счёта меняет арифметику: для активных сальдо конечное =
начальное + Дт − Кт; для пассивных — наоборот; активно-пассивные
(расчёты) дают развёрнутое сальдо по субконто: дебетовое по одному
контрагенту и кредитовое по другому не сворачиваются в одно число.
Проверка равенства встраивается в отчёт/тест, а не делается глазами.

СКД: набор данных запросом, группировки счёт → субконто с промежуточными
итогами, отборы (период, организация, счёт, значение субконто),
ресурсы — суммы остатков и оборотов. Параметры виртуальных таблиц
передаются из настроек периода отчёта.

Сверка с прямым запросом и учебной БП закрывает задание цифрами.

Проверка формулой делается на счёте расчётов 60: развёрнутое сальдо
по контрагентам — дебетовое по одному, кредитовое по другому, свёртка
в одно число будет ошибкой при правильном итоге. Типичные ошибки:
остатки на начало считать своим подзапросом вместо виртуальной
таблицы; признак счёта не учитывать, и пассивные счета показывают
сальдо «вверх ногами»; отчёт принимать без сверки с запросом-ручником.

Проверка понимания: ОСВ активные счета сходится, а по счёту 62
сальдо «не то». Что вы забыли про развёрнутое сальдо активно-
пассивных счетов?

ОСВ доказывает свою цифру разворотом: сальдо счёта раскрывается
до карточки счёта и первичного документа в два перехода. Итоги ОСВ
сверяются с регистром напрямую (обороты за период равны движениям):
отчёт, считающий «по-своему», расходится при первом расхождении
итогов. Настройки отчёта (разворот по субконто, группировки) —
сохраняемые варианты: главный бухгалтер и аудитор смотрят одну
ОСВ разными разворотами, а не тремя разными отчётами.

ЗАДАНИЕ: что сделать
1. Реализуйте отчёт `ОборотноСальдоваяВедомость` на виртуальных таблицах
   регистра бухгалтерии: остатки на начало, обороты Дт/Кт, остатки на конец.
2. Настройте группировки: счёт → субконто; вывод промежуточных итогов по счетам.
3. Добавьте отборы: период, организация, счёт, значение субконто.
4. Реализуйте проверку: сальдо на конец = сальдо на начало + Дт − Кт (для активных).
5. Сверьте отчёт с прямым запросом и с учебной БП (если доступна).

ПОДСКАЗКИ МЕНТОРА:
- Остатки бухгалтерского регистра берутся с учётом признака счёта: для активно-пассивных счетов логика другая. Проверьте на счёте расчётов.
- СКД умеет «остатки на начало» через параметры виртуальной таблицы. Не считайте их вручную в коде отчёта.
