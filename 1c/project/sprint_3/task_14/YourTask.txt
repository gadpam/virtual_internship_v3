ЛЕГЕНДА И КОНТЕКСТ: ситуация и зачем это нужно
Загрузка прайса поставщика на 100 тысячах строк «задумывалась» на минуты:
сопоставление шло вложенными циклами. Лечится это не железом, а выбором правильной
коллекции. Сегодня — на живых замерах.

Коллекции — это рабочий инструмент. Важно понимать, когда что использовать:
Массив для упорядоченного списка, Структура для именованных полей, Соответствие для
поиска по ключу, СписокЗначений для UI, ТаблицаЗначений для наборов данных и передачи
в запрос. Выбор коллекции влияет и на читабельность, и на скорость.

ТЕОРИЯ: что нужно знать перед выполнением
Коллекции 1С различаются назначением и ценой операций. Массив — упорядоченный
список с доступом по индексу; поиск элемента в нём — перебор O(n). Структура —
именованные поля (ключ — строка-идентификатор), удобна для передачи набора
параметров и возврата нескольких значений из функции. Соответствие — пары
«ключ — значение» с хеш-доступом: вставка и поиск в среднем O(1), ключи могут
быть любого типа (число, строка, ссылка). СписокЗначений — коллекция для
интерфейса: элементы с представлением, пометками и картинками. ТаблицаЗначений —
строки с колонками; её можно свернуть, сгруппировать, передать параметром в запрос.

Функция СгруппироватьПоСвойству из задания — канонический приём: один проход по
таблице, и для каждого значения колонки Соответствие хранит массив строк этой
группы. Без соответствия та же задача решается сортировкой или повторными поисками.

НайтиДубликаты показывает цену алгоритма. Наивный вариант сравнивает каждый
элемент с каждым: 100 000 элементов — порядка 10 миллиардов сравнений, O(n^2).
Вариант через Соответствие: один проход, «видели ключ или нет» — O(n) в среднем.
Разница на замере — не проценты, а порядки: секунды против минут.

Граница применимости: таблица значений на сотни тысяч строк в памяти клиентского
процесса — тяжёлая; большие наборы для обработки лучше держать в базе и тянуть
запросом порциями. Коллекция выбирается под операцию, которая будет частой:
частый поиск по ключу — Соответствие, частая передача в запрос — таблица,
порядок важен и доступ по номеру — массив.

Пример группировки из задания «на пальцах»: строки прайса с колонкой Поставщик
превращаются в Соответствие, где ключ — поставщик, а значение — массив его строк.
Дальше каждая группа обрабатывается отдельно без единого повторного поиска
по исходной таблице. Типичная ошибка: использовать Массив как словарь
(«найду индекс перебором») и получить тот самый O(n^2) на ровном месте;
вторая частая: ключом Соответствия берут наименование товара строкой вместо
ссылки — переименовали товар, и «словарь» рассыпался на две группы.
