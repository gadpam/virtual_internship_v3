ЛЕГЕНДА И КОНТЕКСТ: ситуация и зачем это нужно
AI-сервис на стенде есть, но у новичка в Python всё ломается до кода:
не та версия, пакеты в системном интерпретаторе, «у меня не работает».
Сегодня окружение доводится до воспроизводимого: venv, lock, запуск.

Главная проблема новичка в Python — не синтаксис, а окружение: версии,
виртуальные окружения, зависимости, «у меня работает». Минимум Python у вас уже есть
(task_5: venv, скрипт, JSON, HTTP-запрос); здесь доводим окружение до уровня сервиса.

ТЕОРИЯ: что нужно знать перед выполнением
Виртуальное окружение (venv) изолирует зависимости проекта от
системного Python: интерпретатор проекта, свои пакеты, своя версия
каждого пакета. Системный Python не трогают никогда: конфликты версий
между проектами невоспроизводимы и недиагностируемы («вчера работало»).

Зависимости фиксируются: requirements.txt с закреплёнными версиями
(pin) и lock-подход pyproject: установка на чистой машине обязана
дать тот же набор. «Поставьте fastapi» без версии — завтрашняя
поломка без изменения вашего кода.

Запуск сервиса — uvicorn (ASGI-сервер): app.main:app, хост 0.0.0.0,
порт 8010 на стенде (совпадает с docker-compose и README сервиса).
Swagger UI на /docs — живой контракт и первая проверка «сервис
поднялся».

Контейнерный запуск проверяет воспроизводимость окружения:
в Docker сервис собирается из Dockerfile стенда; расхождение
«локально работает, в контейнере нет» — дефект окружения, чинится
сегодня, а не в день интеграции с 1С.

Диагностика чистого старта: коллега по README поднял сервис за
10 минут — lock-файл дал те же версии. Типичные ошибки: ставить
пакеты «последние» без pin; venv создавать внутри системных путей
и терять; расхождение «в контейнере не работает» чинить правкой
кода вместо окружения.

Проверка понимания: назовите артефакт, которым ваша работа
    доказывается постороннему — цифры сверки, таймлайн, протокол,
    тест или таблица метрик. Работа, у которой такого артефакта нет,
    на защите и в споре превращается в «поверьте мне», а квартал
    учил обратному: доверие строится воспроизводимыми доказательствами.

ЗАДАНИЕ: что сделать
1. Установите Python 3.11+ и создайте виртуальное окружение в
   internship/src/ai_service/.venv (или используйте uv).
2. Установите зависимости из requirements.txt (FastAPI, uvicorn, httpx, pytest).
3. Запустите сервис: `uvicorn app.main:app --reload --host 0.0.0.0 --port 8010`
   и откройте документацию Swagger UI.
4. Разберите pyproject/requirements: что означают версии, зачем pin, что такое lock.
5. Добавьте сервис в docker-compose и проверьте запуск в контейнере.

РЕЗУЛЬТАТ (Definition of Done):
- Окружение создано, зависимости установлены без ошибок
- Сервис запускается локально и в контейнере
- Swagger UI открывается и показывает эндпоинты
- В рефлексии объяснено, зачем venv и pin версий

ПОДСКАЗКИ МЕНТОРА:
- Никогда не ставьте пакеты в системный Python: это источник конфликтов, которые потом невозможно воспроизвести.
- Версии зависимостей фиксируйте: «у меня работало вчера» без lock-файла не диагностируется.
