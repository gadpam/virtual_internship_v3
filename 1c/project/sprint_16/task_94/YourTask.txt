ЗАДАНИЕ task_94 · спринт 16 · Q2
Тема спринта: Клиенты внешних API по документации поставщика
Курсы валют, справочники и кеширование внешних данных

Оценка времени: 2 ч
Уровень задания: резерв — буфер квартала; при отставании не выполняется

ЛЕГЕНДА И КОНТЕКСТ: ситуация и зачем это нужно
Цены в долларах у поставщика, курс берётся «с сайта при каждом расчёте» —
и однажды сайт лёг, а с ним встали все поступления. Сегодня курсы становятся
локальными данными с расписанием, запасом прочности и проверкой на аномалии.

Часть внешних данных меняется предсказуемо (курсы валют — раз в день)
и нужна почти во всех расчётах. Правильный подход: загрузка по расписанию, хранение
локально, использование локальной копии, а не вызов API на каждый расчёт.

ТЕОРИЯ: что нужно знать перед выполнением
Принцип задания: внешние справочные данные копируются в систему по
расписанию и дальше используются локально. РС «КурсыВалют» (валюта, дата,
курс, источник) — источник правды внутри RIH: расчёт документа читает
срез последних на свою дату и никогда не ходит в API посреди проведения
(внешний вызов в транзакции — запрет из task_44).

Fallback: источник недоступен — берём последний известный курс и поднимаем
предупреждение в журнал/оператору. Молча использовать вчерашний курс
нельзя, молча падать — тем более: деградация должна быть видимой.

Аномалия (скачок больше порога, у нас 30%) — стоп-сигнал: опечатка в
источнике способна переценить весь учёт. Курс ставится «на подтверждение»,
автоматика ждёт человека. Порог — настройка, а не константа в коде.

Локальная копия — не кэш из task_60: кэш можно выбросить, копию курсов
нельзя, по ней уже посчитаны документы. Поэтому у записи курса есть
источник и время загрузки: курс «откуда-то» в аудите не защищается.

Тест аномалии: mock отдаёт курс +35% — загрузка обязана остановиться
и поднять предупреждение, а документы продолжить считаться по
последнему нормальному курсу. Типичные ошибки: курс хранить числом
в константе «на всех» (нет истории и даты); аномальный курс применить
и потом «исправлять документы руками»; fallback делать молчаливым —
бухгалтер узнаёт о недельном старом курсе из спора с поставщиком.

Проверка понимания: курс в документе за прошлый месяц при пересчёте
сегодня обязан остаться курсом даты документа. Если ваш код взял
сегодняшний — вы переписали историю учёта.

Внешние справочные данные имеют владельца свежести: курсы валют
устарели на день — это видимое состояние, а не тихая цифра.
Кеш курсов инвалидируется по дате, а не по «перезапустился сервер»:
курс на дату документа берётся исторически, а не сегодняшний
(task_42 с подписями — та же логика времени). Источник недоступен —
работаем на последнем известном курсе с пометкой в журнале;
молча подменять курс нулём запрещено категорически. Курсы —
создаваемый в задании регистр, а не найденный готовым.

2. Реализуйте fallback: если источник недоступен, использовать последний известный курс
   и поднять предупреждение.
3. Добавьте проверку аномалий: курс изменился более чем на 30% — требуется подтверждение.
4. Используйте локальные курсы в расчёте суммы документа (доработка из Q1):
   если у документа нет реквизита «Валюта», добавьте его — пересчёт в рубли
   идёт по курсу из РС на дату документа, а не по живому вызову API.
5. Опишите: какие ещё справочники стоит загружать локально и почему.

РЕЗУЛЬТАТ (Definition of Done):
- Загрузка по расписанию работает, курсы хранятся локально
- Fallback реализован и проверен на остановленном mock
- Проверка аномалий срабатывает (тест на искусственном скачке)
- Расчёт документа использует локальные курсы

ПОДСКАЗКИ МЕНТОРА:
- Аномалия курса — реальный кейс: опечатка поставщика может изменить цены в 10 раз. Лучше остановить загрузку, чем испортить учёт.
- Локальная копия данных — это не «кэш, который может устареть», а источник для учёта. Разница в ответственности.
