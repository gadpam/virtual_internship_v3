ЗАДАНИЕ task_82 · спринт 14 · Q2
Тема спринта: HTTP-сервисы в 1С: публикуем свой API
Версионирование API и единый формат ошибок

Оценка времени: 3 ч
Уровень задания: ядро — обязательное; без него спринт не закрыт

КОНТЕКСТ: зачем это нужно
Контракты живут годами, а партнёры обновляются в разное время. Поэтому
нужны версии API и единый, предсказуемый формат ошибки: код, сообщение, детализация,
идентификатор инцидента для поддержки.

ЗАДАНИЕ: что сделать
1. Реализуйте версионирование через URL (/api/v1/...) и проверьте, что
   v1 и v2 могут сосуществовать.
2. Спроектируйте единый формат ошибки: {code, message, details, incidentId, timestamp}.
3. Реализуйте общий обработчик ошибок сервиса: любое исключение → формат ошибки +
   запись в журнал регистрации с incidentId.
4. Составьте справочник кодов ошибок RIH (минимум 12 кодов) и положите в документацию.
5. Напишите тесты: 400 на мусор, 401 без ключа, 404 на неизвестный ресурс, 500 с incidentId.

РЕЗУЛЬТАТ (Definition of Done):
- Версии API сосуществуют, переключение работает
- Единый формат ошибки реализован для всех маршрутов
- Справочник кодов ошибок добавлен в internship/docs/api/error_format.md
- 5+ тестов на ошибки проходят

ПОДСКАЗКИ МЕНТОРА:
- incidentId должен возвращаться пользователю и писаться в лог: так поддержка находит проблему по одной строке из письма.
- Не меняйте смысл кода ошибки в существующей версии — это ломает клиентов. Новое поведение — в новой версии.
