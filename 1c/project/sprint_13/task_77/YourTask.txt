ЗАДАНИЕ task_77 · спринт 13 · Q2
Тема спринта: Интеграции: протоколы, форматы, контракты, инструменты
OpenAPI 3.x: контракт как источник истины

Оценка времени: 3 ч
Уровень задания: ядро — обязательное; без него спринт не закрыт

КОНТЕКСТ: зачем это нужно
Контракт-first подход: сначала описываем API в OpenAPI, потом реализуем.
Это позволяет партнёру начать работу до вашей реализации, а вам — сгенерировать
моки и тесты. Без контракта интеграция превращается в переписку «а что вы имели в виду?»

ЗАДАНИЕ: что сделать
1. Опишите в OpenAPI 3.0 API подсистемы «Заказы онлайн-магазина»: 5 операций,
   схемы запросов и ответов, коды ошибок, авторизация по bearer-токену.
2. Сохраните спецификацию в internship/docs/api/openapi.yaml.
3. Сгенерируйте по ней mock (или проверьте в Swagger UI) и убедитесь, что пример
   проходит валидацию схемой.
4. Реализуйте валидацию входящего JSON по схеме (в mock-сервисе на Python — как
   задел под task_129).
5. Согласуйте контракт с «партнёром» (ментором/командой) и зафиксируйте версии.

РЕЗУЛЬТАТ (Definition of Done):
- openapi.yaml валиден (проверено линтером/валидатором)
- 5 операций со схемами, ошибками и авторизацией описаны
- Примеры запросов проходят валидацию схемой
- Контракт согласован, версия зафиксирована (1.0.0)

ПОДСКАЗКИ МЕНТОРА:
- Пишите description к каждому полю: партнёр не должен угадывать, что такое `status: 3`.
- Версия контракта обязательна. Без неё «мы поменяли формат» станет сюрпризом в продуктиве.
