ЛЕГЕНДА И КОНТЕКСТ: ситуация и зачем это нужно
Нагрузка Q1 росла внутри одной базы. Теперь мир стал больше: магазин присылает
заказы, банк — выписки, поставщик — остатки. Первая тема квартала — слово
«интеграция»: прежде чем писать код, учимся описывать обмены словами.

Прежде чем писать код, интеграции проектируют: список систем, направление
данных, периодичность, объёмы, критичность, что происходит при сбое. Без карты вы
получите зоопарк обменов, который невозможно поддерживать.

ТЕОРИЯ: что нужно знать перед выполнением
Интеграция — обмен данными между системами. Три стиля: обмен файлами
(выгрузил—отправил—загрузил), программные интерфейсы (API: система отвечает
на запросы), события/очереди (источник публикует факт, подписчики разбирают).
Они различаются задержкой, связностью (потребитель должен быть онлайн?),
гарантиями доставки и ценой. Сравнение из DoD — не табличка ради таблички:
выбор стиля для заказа и для выписки банка обоснованно разный.

Документ интеграции описывает обмен до кода: участники, направление, объект
обмена, формат и версия, идемпотентность (что будет при повторной доставке),
ошибки и повторы, мониторинг. У заказа: идемпотентность по внешнему
идентификатору магазина; у выписки: повтор «выписка за дату» безопасен
перезаписью того же периода — такие решения живут в документе, а не в голове
разработчика.

Стратегия квартала располагает темы по слоям: HTTP и форматы → веб-сервисы
1С → обмены файлами и правила → REST API вокруг RIH → очереди и брокеры →
сложные форматы и мониторинг. Каждая следующая тема пользуется контрактами
предыдущих, поэтому пробелы здесь дорого стоят позже.

Аудит README и tools — инвентаризация стенда перед сезоном: что уже есть
(mock_shop_api, xlsx/csv образцы), что понадобится установить (requests,
Postman).

Мини-пример по трём стилям: заказ из магазина — API (нужен ответ сразу:
принят/нет), выписка банка — файлы или SOAP по расписанию (срочности
нет, важна полнота за день), остатки для витрин — события/выгрузки
пакетами. Типичные ошибки выбора: API «потому что современно» туда,
где партнёр бывает офлайн сутками; файлы туда, где нужен ответ за
секунду; события без документа идемпотентности (повторная доставка —
норма, а не авария). Документ интеграции пишется до кода: в Q2 вы
проверите, как он пережил первый же настоящий обмен.
