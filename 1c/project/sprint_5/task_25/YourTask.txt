Тема спринта: Язык запросов 1С: от простого к оптимизированному
Основы языка запросов: выборка, условия, порядок

Оценка времени: 2 ч
Уровень задания: ядро — обязательное; без него спринт не закрыт

ЛЕГЕНДА И КОНТЕКСТ: ситуация и зачем это нужно
Первое боевое крещение в консоли запросов: ментор смотрит на ваш справочник
и говорит: «Покажи товары, у которых до сих пор нет цены. Одним запросом».
Сегодня язык запросов из «похожего на SQL» становится рабочим инструментом.

Язык запросов 1С похож на SQL, но не совпадает с ним: свои виртуальные
таблицы, свои особенности соединений, своё поведение с Null. Консоль запросов —
главный инструмент разработчика: в ней вы будете проводить половину жизни.

ТЕОРИЯ: что нужно знать перед выполнением
Язык запросов 1С похож на SQL, но работает не с физическими таблицами, а с объектами
конфигурации: Справочник.Номенклатура, РегистрНакопления.ТоварыНаСкладах.Остатки.
Платформа сама переводит запрос в SQL вашей СУБД и сама следит за правами и RLS:
запросом нельзя прочитать то, что пользователю запрещено ролями.

Анатомия запроса: ВЫБРАТЬ поля ИЗ источник ГДЕ условия СГРУППИРОВАТЬ ПО …
УПОРЯДОЧИТЬ ПО … . ВЫБРАТЬ РАЗЛИЧНЫЕ убирает полные дубликаты строк результата —
дорогая операция сортировки, ею не лечат дубли от соединений. ПЕРВЫЕ N ограничивает
выдачу после сортировки: без УПОРЯДОЧИТЬ «первые пять» — пять случайных.
Виртуальные таблицы (Остатки, Обороты, СрезПоследних) вызываются с параметрами
в скобках — периодом и отборами; это не украшение, а способ дать платформе
посчитать маленький набор вместо всей таблицы.

NULL в запросах 1С — «значение отсутствует»: пустая ссылка, незаполненный реквизит,
отсутствующая правая часть левого соединения. Сравнения с NULL не дают ни истины,
ни лжи: условие Цена <> 0 молча выбросит строки, где цены нет. Инструменты:
ЕСТЬ NULL в условии (Цена ЕСТЬ NULL — проверки «нет значения»), функция
ЕСТЬNULL(Поле, Замена) подставляет значение по умолчанию, ЕСТЬ в подзапросах —
проверка существования. Анти-соединение «товары без цены» пишется двумя способами:
НЕ В (подзапрос с ценами) — опасно при NULL в подзапросе, и ЛЕВОЕ СОЕДИНЕНИЕ
с проверкой правой части на NULL — надёжно и читаемо.

Параметры (&Дата, &Склад) — единственный способ передавать значения (см. task_18):
текст запроса статичен, план переиспользуется. Консоль запросов EDT — место,
где запрос отлаживают на живых данных с реальными параметрами до вставки в код.

Пример анти-соединения из задания, надёжный вариант: ВЫБРАТЬ Товары.Ссылка
ИЗ Справочник.Номенклатура КАК Товары ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.
ЦеныНоменклатуры.СрезПоследних(&Дата, ) КАК Цены ПО Цены.Номенклатура =
Товары.Ссылка ГДЕ Цены.Цена ЕСТЬ NULL. Типичная ошибка новичка: условие
«ГДЕ НЕ Товары.Ссылка В (запрос цен)» — стоит в ценах появиться строке
с пустой номенклатурой, и НЕ В начнёт выбрасывать всё подряд из-за NULL.

ЗАДАНИЕ: что сделать
1. Откройте консоль запросов и напишите 5 запросов: все товары; товары группы;
   товары с ценой выше заданной; движения за период; документы, не проведённые.
2. Освойте ВЫБРАТЬ РАЗЛИЧНЫЕ, ГДЕ, УПОРЯДОЧИТЬ ПО, ПЕРВЫЕ N, ИТОГИ.
3. Разберитесь, что такое Null в запросах 1С и как с ним работать (ЕСТЬ, ЕСТЬNULL).
4. Напишите запрос, который находит товары без цены на текущую дату (анти-соединение).
