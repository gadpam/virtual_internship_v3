ЛЕГЕНДА И КОНТЕКСТ: ситуация и зачем это нужно
Интеграционная команда прислала план продаж файлом CSV и задала простой вопрос:
«Ваш скрипт это прочитает? А если файл битый — упадёт молча или скажет, что не так?»
Python в этом проекте — не второй язык ради языка, а рабочий инструмент рядом с 1С.

Python встретится вам раньше, чем кажется: в Q2 вы вызываете внешние API и
читаете ответы сервисов, в Q4 работаете рядом с AI-командой (sprint_39 углубит
окружение, FastAPI и тесты). Сейчас нужен минимум, чтобы не утонуть в окружении:
запустить скрипт, прочитать CSV и JSON, сделать HTTP-запрос, обработать ошибку.
Глубокий Python здесь не требуется - требуется рабочий.

ТЕОРИЯ: что нужно знать перед выполнением
Python-скрипт в этом проекте — одноразовый инженерный инструмент: прочитать файл,
проверить сервис, подготовить данные. Виртуальное окружение (venv) изолирует
зависимости скрипта от системного Python: пакеты ставятся внутрь папки .venv,
а не «в компьютер вообще». Активировали venv — python и pip указывают внутрь него.
Само окружение в Git не коммитится: оно пересоздаётся из списка зависимостей
(requirements.txt, вывод pip list/pip freeze), который как раз коммитится.

Модуль csv читает табличные файлы. Три вещи, на которых падают новички: разделитель
(в наших файлах это «;», а не запятая), кодировка (utf-8) и заголовок первой строки.
csv.DictReader превращает каждую строку в словарь по заголовкам — колонку берут
по имени (planned_quantity), а не по номеру, и переживают перестановку колонок.
Модуль json пишет результат так, чтобы его могла прочитать другая программа:
json.dump(структура, файл, ensure_ascii=False, indent=2).

HTTP через стандартную библиотеку: urllib.request.urlopen(url) возвращает объект
ответа со статусом (response.status), заголовками (response.headers) и телом
(read().decode('utf-8')). Статусы делятся на семейства: 2xx — успех, 4xx — ошибка
клиента (не тот запрос, нет ключа), 5xx — ошибка сервера. Учебный mock умеет
специально отвечать 500 (fault-режим error500) — так проверяют обработку ошибок,
а не «надеются, что прод не упадёт».

Обработка ошибок строится на исключениях: нет файла — FileNotFoundError, битый
JSON — json.JSONDecodeError, сеть и статусы >= 400 — urllib.error.HTTPError/URLError.
Каждую ошибку скрипт обязан превратить в понятное сообщение человеку и ненулевой
код возврата (sys.exit(1)), чтобы вызывающий код и CI видели неудачу.
Детерминированность — повторяемость результата на одних данных — проверяется
двойным запуском: сводки обязаны совпасть байт в байт.

Пример HTTP-запроса из задания (сокращённо):
  import urllib.request
  req = urllib.request.Request("http://localhost:8020/health")
  with urllib.request.urlopen(req, timeout=10) as r:
      print(r.status, r.headers.get("Content-Type"), r.read()[:200])
Типичные ошибки: забыть активировать venv и поставить пакеты в системный Python;
читать CSV с разделителем по умолчанию (запятая) и получать «одну большую колонку»;
ловить все ошибки одним пустым except и потом не понимать, что именно упало;
печатать итог через print вместо JSON-файла — результат нельзя проверить автоматически.

ЗАДАНИЕ: что сделать
1. Проверьте окружение: python --version (нужен 3.11+), создайте виртуальное
   окружение и зафиксируйте вывод pip list. Запишите версии в VERSIONS.md.
2. Напишите скрипт internship/src/scripts/first_python_check.py: он читает
   internship/data/sales_plan_sample.csv (разделитель `;`, колонка количества —
   planned_quantity), считает строки и итоги и пишет сводку в JSON-файл.
3. Добавьте HTTP-запрос стандартным urllib: получите ответ учебного сервиса
   (mock_shop_api из docker compose: GET http://localhost:8020/health — или
   локальный python -m http.server) и запишите статус, один заголовок и тело ответа.
4. Добавьте обработку ошибок: нет файла, битый JSON, HTTP-ошибка. Ошибку 500
   получите от mock в fault-режиме: параметр `?fault=error500` или заголовок
   `X-Fault-Mode: error500`. Каждой ошибке - понятное сообщение и ненулевой код возврата.
5. Запустите скрипт дважды подряд: результат одинаковый и воспроизводимый.

РЕЗУЛЬТАТ (Definition of Done):
- Скрипт first_python_check.py запускается в venv и пишет JSON-сводку по CSV
- HTTP-запрос выполнен; статус, заголовок и тело ответа зафиксированы
- Три ошибки (файл, JSON, HTTP 500) обрабатываются с понятными сообщениями
- Версии Python и пакетов записаны в VERSIONS.md

ПОДСКАЗКИ МЕНТОРА:
- venv не коммитится в Git: окружение пересоздаётся из списка зависимостей. Если «забыл активировать venv» - это самая частая причина «у меня работает».
- Сначала добейтесь, чтобы скрипт работал на хороших данных. Ошибки добавляйте вторым шагом, иначе не поймёте, что именно сломалось.
