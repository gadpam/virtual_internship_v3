Тема спринта: Инструменты разработки: Конфигуратор, EDT, Git, Docker, Python-минимум
Выгрузка конфигурации в файлы и структура исходников

Оценка времени: 2 ч
Уровень задания: ядро — обязательное; без него спринт не закрыт

КОНТЕКСТ: зачем это нужно
Чтобы положить конфигурацию в Git, её надо превратить в набор текстовых
файлов. Есть два пути: выгрузка «в файлы» средствами конфигуратора/EDT и проектная
структура EDT (Configuration.xml + папки Catalogs, Documents, Reports и т.д.).
Мы работаем по второму пути: он даёт стабильные диффы и возможность ревьюить код.

ЗАДАНИЕ: что сделать
1. Изучите структуру папки `internship/Configuration/`: найдите Configuration.xml,
   папки CommonModules, Catalogs, Documents, DataProcessors, Roles, Subsystems.
2. Откройте один общий модуль и посмотрите, как выглядит исходник: файл Module.bsl.
3. Добавьте в общий модуль `РИХ_ОбщегоНазначения` новую экспортную процедуру-заглушку
   `ПроверитьОкружение()` с комментарием и вызовом `Сообщить()` внутри.
4. Обновите конфигурацию базы RIH_DEV и вызовите процедуру через «Сервис → Консоль кода»
   или внешнюю обработку.
5. Посмотрите `git diff` и убедитесь, что видно ровно вашу правку и ничего лишнего.

РЕЗУЛЬТАТ (Definition of Done):
- Изменение видно в git diff как несколько строк текста, а не как «изменён бинарный файл»
- Процедура вызывается и печатает сообщение
- В рефлексии описано, из каких папок состоит проект EDT и где живёт код модуля
- Конфигурация обновилась без ошибок и предупреждений

ПОДСКАЗКИ МЕНТОРА:
- Префикс РИХ_ (Retail Integration Hub) — соглашение именования подсистемы. Оно понадобится в task_10 и будет проверяться на code review.
- Если git diff показывает «файл изменён целиком», проверьте кодировку и переводы строк: core.autocrlf должен быть false, файлы — UTF-8.
- Module.bsl — обычный текст, его можно открывать в любом редакторе, но правьте всё-таки через EDT, чтобы не потерять метаданные.

МАТЕРИАЛЫ И ССЫЛКИ:
