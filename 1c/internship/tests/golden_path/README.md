# Золотой путь года (task_302, task_303)

Один сценарий, который связывает **все контуры системы**: магазин → RIH →
склад и лояльность → доставка → бухгалтерия → витрины и BI → инцидент и трекер.
Это «день из жизни холдинга» в проверяемом виде.

| Файл | Что делает |
|---|---|
| `test_golden_path.py` | сквозной сценарий по API: 15 шагов с проверками на каждом |
| `NEGATIVE_BRANCH.md` | негативная ветка: что должно произойти при сбое партнёра |

Сценарий в интерфейсе 1С описан в `tools/ci/vanessa/features/golden_path.feature`
(прогон vanessa-runner). Python-версия здесь — та же история, но без платформы,
поэтому она выполняется в CI на каждом коммите.

## Правила золотого пути

1. **Шаги нумеруются.** Провал на шаге 7 должен называться «шаг 7: бонусы», а не
   «упал assert».
2. **Каждый шаг имеет проверку**, а не только действие.
3. **Данные создаются уникальными** (`GOLD-<uuid>`), чтобы прогон не зависел от
   предыдущих запусков.
4. **Негативная ветка обязательна**: золотой путь без неё проверяет только то,
   что и так работает.
5. Сценарий **документируется**: список шагов, ожидаемые артефакты, время прогона.
   Это вход для task_304 (единый комплект документации) и task_308 (демо).
