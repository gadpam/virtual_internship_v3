# Интеграционные тесты (L3, task_141)

Проверяют **взаимодействие компонентов**, а не отдельную функцию: клиент → mock-сервис
→ очередь → консьюмер → HTTP-сервис 1С → журнал. Один тест здесь стоит десяти
модульных, потому что ловит ошибки на стыках: кодировки, таймауты, порядок полей,
поведение при повторной доставке.

| Файл | Что проверяет |
|---|---|
| `test_partner_chain.py` | цепочка «заказ магазина → лояльность → транспортная компания» на живых mock-сервисах |
| `test_fault_handling.py` | матрица сбоев из `fixtures/faults_matrix.json`: ретраи, таймауты, 429, деградация |

## Требования к стенду

```bash
cd 1c/internship/tools
docker compose -f docker-compose.test.yml up -d --wait
cd ../tests && pytest -q integration
```

Если стенд не поднят, тесты пропускаются (`require_stand` в `conftest.py`) —
но пропуск не означает «всё хорошо»: в отчёте по заданию укажите, какие тесты
реально выполнялись.

## Что считается дефектом интеграции

1. Клиент 1С падает с необработанным исключением при 500 или таймауте.
2. Повторная доставка создаёт второй документ (нарушена идемпотентность).
3. Ошибка партнёра не попала в журнал интеграций — её невозможно расследовать.
4. Таймаут больше, чем у вызывающей стороны: цепочка «висит» вместо быстрой ошибки.
5. Ответ не соответствует задокументированному контракту (ловится на уровне L2).
