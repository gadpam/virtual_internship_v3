# Сценарии нагрузки

| Сценарий | Профиль | RPS | Длительность | Назначение |
|---|---|---|---|---|
| `baseline` | ровная нагрузка | 5 | 60 с | базовая латентность, точка отсчёта |
| `target` | целевая нагрузка рабочего дня | 20 | 120 с | проверка SLO p95 ≤ 2 с |
| `peak` | утренний пик (10:00–11:00) | 60 | 120 с | точка деградации |
| `step` | ступени 5 → 10 → 20 → 40 → 80 | по 45 с | 225 с | профиль «нагрузка → латентность» |
| `soak` | умеренная нагрузка надолго | 15 | 600 с | утечки, рост очереди, деградация со временем |
| `spike` | резкий всплеск | 5 → 200 → 5 | 90 с | поведение circuit breaker и очередей |

## Параметры для каждого сценария

```bash
python3 ../../src/scripts/generate_load.py \
  --url http://localhost:8020/api/v1/products \
  --header "X-Api-Key:mock-shop-key" \
  --rps 20 --duration 120 --expect 200 \
  --output ../../build/load/target.json

python3 ../../src/scripts/report_metrics.py ../../build/load/target.json --slo-p95 2.0
```

## Правила

1. Сценарий описывается **до** прогона: нагрузка, длительность, ожидаемый SLO.
   Иначе результат подгоняется под вывод.
2. Между прогонами — пауза не меньше 30 секунд: кеш и пул соединений должны
   прийти в равновесие.
3. Один прогон — один сценарий. Смешанные нагрузки неинтерпретируемы.
4. Результат сохраняется в `internship/build/load/` с датой и параметрами — это
   ваш базлайн для сравнения после оптимизации (task_192, task_201).
