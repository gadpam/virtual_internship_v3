# Нагрузочные тесты (L4, task_143, task_201)

Цель — не «нагрузить сервер до отказа», а **получить профиль**: какая нагрузка
целевая, какая пиковая, где деградация начинается и что именно деградирует.

| Файл | Что делает |
|---|---|
| `test_load_profile.py` | снимает профиль mock-сервисов: p50/p95/p99 при ступенчатой нагрузке |
| `scenarios/README.md` | сценарии нагрузки и их параметры |

Инструмент — `src/scripts/generate_load.py` (простой генератор RPS) и
`src/scripts/report_metrics.py` (сводка против SLO). Для серьёзных прогонов 1С
используйте JMeter/Gatling и `1c/project/tools/Environment.md`.

## Запуск

```bash
cd 1c/internship/tests
pytest -q -m load            # медленно: несколько минут
```

## Что фиксируется в отчёте

| Показатель | Зачем |
|---|---|
| целевая нагрузка (RPS) и пиковая | границы, в которых система обязана работать |
| p50 / p95 / p99 | SLO формулируется по p95, а не по среднему |
| доля ошибок при каждом уровне | деградация видна раньше, чем отказ |
| точка деградации | нагрузка, после которой p95 растёт нелинейно |
| поведение при 429 | уважает ли клиент `Retry-After` |
| восстановление после пика | возвращается ли p95 к базовому уровню |

Отчёт без точки деградации — не профиль, а один замер. Профиль отвечает на вопрос
«сколько пользователей выдержим и что сломается первым» (вход для task_202,
capacity planning).
