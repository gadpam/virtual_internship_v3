# Сквозные сценарии (L3, task_142)

E2E-тест идёт **от действия пользователя до результата в другой системе**: нажал
кнопку в форме 1С → документ проведён → данные ушли партнёру → запись появилась
в журнале и витрине. Это самый дорогой уровень: медленный, хрупкий, но именно он
отвечает на вопрос «работает ли система».

## Разделение ответственности с vanessa

| Инструмент | Что покрывает |
|---|---|
| `tests/features/*.feature` + vanessa-runner | сценарии в интерфейсе 1С (формы, команды, сообщения пользователю) |
| `tests/e2e/test_business_scenario.py` | сквозная проверка по API: магазин → RIH → партнёры → витрина, без интерфейса |
| `tests/golden_path/` | золотой путь года как единый сценарий с негативной веткой (task_302) |

Python-часть e2e намеренно не требует 1С: она проверяет контракт поведения всей
цепочки на mock-сервисах и витринах. Когда вы подключите свою базу RIH, тот же
сценарий прогоняется vanessa-фичами — две половины одного теста.

## Правила e2e

1. **Один сценарий — одна бизнес-история.** Не «проверим все кнопки».
2. **Данные создаёт сам тест** и сам за собой убирает (или использует уникальные id).
3. **Ожидание — явное.** Никаких `sleep(5)`: опрос состояния с таймаутом и интервалом.
4. **Провал e2e блокирует релиз** (L3 в `tools/ci/github-actions/ci.yml`).
5. **Скриншоты и логи** при падении сохраняются в `internship/build/test-reports/`.
