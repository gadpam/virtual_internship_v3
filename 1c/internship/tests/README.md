# Тесты учебного стенда RIH

Уровни тестирования (task_139–144, task_266) и сквозные проверки года
(task_302, task_303). Тесты — не «галочка для CI», а способ перестать бояться
менять код.

## Структура

| Каталог | Уровень | Что проверяет | Задания |
|---|---|---|---|
| `unit/` | L1 | отдельные функции и модули без внешних зависимостей | task_52, task_232 |
| `contract/` | L2 | соответствие API партнёров контракту: схемы, коды, заголовки | task_140 |
| `integration/` | L3 | взаимодействие компонентов стенда: очередь → консьюмер → 1С | task_141 |
| `e2e/` | L3 | сквозной сценарий по API: магазин → RIH → партнёры → трекер | task_142 |
| `load/` | L4 | профиль нагрузки: RPS, p95/p99, деградация | task_143, task_201 |
| `golden_path/` | L3 | золотой путь года + негативная ветка | task_302 |
| `legacy/` | L1 | characterization-тесты легаси-кода до рефакторинга | task_217, task_218 |
| `fixtures/` | — | учебные данные и заготовки ответов | все |
| `features/` | L3 | сценарии vanessa (Gherkin, `# language: ru`) — интерфейс 1С | task_53, task_142 |

## Запуск

```bash
cd 1c/internship/tests
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

pytest -q                       # всё (кроме медленных: они под маркером slow)
pytest -q unit legacy           # L1: модульные и characterization-тесты легаси
pytest -q contract              # L2 (нужен поднятый docker-compose.test.yml)
pytest -q integration e2e       # L3: цепочки и сквозной сценарий
pytest -q -m load               # L4: медленно, несколько минут
pytest -q golden_path           # золотой путь года (L3)
pytest -q --cov=../src --cov-report=term-missing
```

Перед `contract`/`integration`/`e2e` поднимите тестовый стенд:

```bash
cd ../tools && docker compose -f docker-compose.test.yml up -d --wait
```

## Правила написания тестов

1. **Один тест — одно поведение.** Название читается как предложение:
   `test_repeat_delivery_with_same_idempotency_key_returns_duplicate_flag`.
2. ** Arrange–Act–Assert.** Данные подготовлены явно, действие одно, проверки —
   на результат, а не на внутренности.
3. **Изоляция.** Тесты не зависят от порядка запуска и не пишут в общие данные.
   Состояние mock-сервисов сбрасывается перезапуском контейнера.
4. **Никаких секретов и абсолютных путей.** Адреса — из `conftest.py` и
   переменных окружения (`RIH_SHOP_URL` и т. п.).
5. **Проверка негативных веток обязательна.** Тест «создали заказ» без теста
   «партнёр вернул 500» не покрывает то, что ломается в проде.
6. **Падающий тест — ценнее зелёного.** Если тест никогда не падал, проверьте,
   что он действительно что-то проверяет: сломайте код намеренно.

## Порог покрытия

Минимум 70% по строкам для кода интеграций и AI-сервиса (установлен в CI).
Покрытие — индикатор, а не цель: 100% покрытия без проверки негативных сценариев
бесполезно, а 40% с хорошими контрактными тестами спасают релиз.
