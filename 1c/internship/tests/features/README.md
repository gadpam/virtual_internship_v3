# Сценарии vanessa для интерфейса 1С (task_53, task_142)

Здесь живут сценарии, которые прогоняются vanessa-runner против **информационной
базы**: они нажимают кнопки, заполняют формы и проверяют сообщения пользователю.
Сквозные сценарии года (без интерфейса) — в `tools/ci/vanessa/features/`.

| Файл | Что покрывает |
|---|---|
| `orders_import.feature` | приём заказов из магазина: форма журнала, команды, сообщения |
| `price_calculation.feature` | расчёт цены выгрузки: форма, проверка правил из `legacy/` |

## Прогон

```bash
cd 1c/internship/tools/vanessa
oscript ./vanessa-runner.epf --settings vanessa-runner.json
```

В CI сценарии проверяются на структуру (первая строка `# language: ru`, наличие
хотя бы одного сценария) — см. `tools/ci/github-actions/ci.yml`, задание L3.

## Как писать сценарий

1. Первая строка — `# language: ru`.
2. `Функционал:` — что проверяем, с точки зрения пользователя.
3. `Предыстория:` — подготовка данных (не проверки!).
4. Шаги — только через шаги vanessa: «Когда я …», «Тогда …».
5. Проверка — на видимый результат: значение в поле, сообщение, наличие строки
   в списке, а не на внутреннее состояние.
6. Один сценарий ≤ 15 шагов. Больше — делите на два.

## Чего в сценариях быть не должно

- GUID, внутренних идентификаторов, «магических» ссылок на объекты;
- `sleep`-подобных ожиданий без условия (vanessa умеет ждать появления элемента);
- проверки реализации («вызвался метод X») — только поведение;
- данных, которые сценарий не создал сам.
