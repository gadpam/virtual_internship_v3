# Characterization-тесты легаси (task_218)

Тесты фиксируют **текущее** поведение `legacy/LegacyPriceModule.bsl` через его
Python-порт `legacy/legacy_rules.py`. Они отвечают на вопрос «что делает код
сейчас», а не «что он должен делать».

Запуск (внешние сервисы не нужны):

```bash
cd 1c/internship/tests && pytest -q legacy
```

## Что здесь зафиксировано

- порядок применения правил (тип цены → весовой → количество → клиент → надбавка
  → округление → себестоимость → неотрицательность);
- странности: неизвестный тип цены молча трактуется как розница;
- баги: пакетный расчёт всегда использует количество 1; `ВыгрузитьЦены` глотает
  исключение;
- **артефакты округления**: `int(price * 100) / 100` на двоичной арифметике даёт
  9.69 вместо 9.70 и 8.54 вместо 8.55 — это видно только потому, что поведение
  зафиксировано числами.

## Как пользоваться при рефакторинге (task_219)

1. Прогоните тесты — все зелёные.
2. Сделайте одно изменение в 1С-коде (переименование, выделение функции).
3. Прогоните тесты снова. Красные — значит, вы изменили поведение, а не структуру.
4. Повторяйте. Рефакторинг без зелёных тестов — это переписывание с неизвестным
   результатом.
5. Если тест «мешает» (фиксирует баг) — не удаляйте его. Заведите отдельный тест
   с ожидаемым правильным поведением, пометьте `xfail` и ссылкой на согласование
   с владельцем.

## Что НЕ покрыто и почему

- `ВыгрузитьЦены` (HTTP-выгрузка) — требует платформы 1С; поведение фиксируется
  сценарием vanessa в `tests/features/` и разбором в task_217.
- `ПриИзмененииТипаЦены` (сброс кеша) — кеш в расчёте не участвует (мёртвый код),
  удаляется при рефакторинге.
