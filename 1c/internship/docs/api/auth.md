# Аутентификация интеграций RIH (task_133)

Вечные API-ключи заменяются токенами со сроком жизни и отзывом.
Ключи остаются переходным механизмом на время миграции клиентов
и проверяются той же единой точкой после токенов.

## Поток client_credentials

```
POST /api/v1/token
{"client": "shop", "secret": "<секрет, показан один раз>"}
→ 200 {"access_token": "...", "token_type": "Bearer", "expires_in": 3600}

GET /api/v1/products
Authorization: Bearer <access_token>
```

- Токен живёт 3600 с, привязан к клиенту и его роли; права роли
  минимальны по операциям (ключ каталога не проводит документы).
- В базе и логах хранятся только SHA-256 хеши: токена
  (`ТокеныИнтеграций`) и секретов (`КлиентыИнтеграций`). Токен и
  секрет показываются клиенту один раз при выдаче/ротации.
- Проверка — единая точка сервиса (`РИХ_Интеграции.КлючДопустим`
  спрашивает `РИХ_Токены.ТокенДопустим` до ключа): маршруты не
  проверяют доступ по-своему, забытый маршрут невозможен, попытки
  пишутся в журнал одним местом.

## Отзыв и ротация

- Отзыв токена (`ОтозватьТокен`) действует немедленно, не в конце
  TTL: утёкший токен умирает в минуту отзыва.
- Ротация секрета без простоя: новый секрет действует сразу,
  предыдущий живёт в окне grace 24 часа, пока клиент переключится;
  дальше старый секрет — 401.
- Утёк ключ партнёра (проверка понимания): за первый час — отозвать
  токены клиента и ротировать секрет, выдать новый по каналу вне
  репозитория, проверить журнал попыток за окно жизни утёкшего
  секрета. Дизайн делает лёгкими отзыв и журнал; медленным остаётся
  только доставка нового секрета партнёру — она вне системы.

## Запреты

- Секреты и токены не передаются в URL (URL целиком живёт в логах
  прокси) — только заголовки.
- Секрет не пишется в журнал ни в каком виде, включая «для отладки».
- Сравнение секрета — по хешу; равенство открытых строк не используется.
