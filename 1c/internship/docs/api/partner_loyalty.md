# Контракт программы лояльности (LOYA) · task_92, task_130

Mock-сервис: `src/mock_loyalty_api` · порт `8021` · через nginx `/loyalty/`.
Авторизация: `X-Api-Key` (`MOCK_LOYALTY_API_KEY`).

## Модель

Баллы — **деньги клиента**. Поэтому:

1. каждая операция имеет уникальный `operation_id` — ключ идемпотентности;
2. повтор с тем же ключом возвращает исходный результат и `duplicate: true`;
3. отмена выполняется отдельным методом `/reverse` и допускается **ровно один раз**;
4. списание больше баланса — ошибка 422, а не «уход в минус».

## Методы

### `GET /api/v1/cards/{card}/balance`

Ответ: `{ "card": string, "balance": float, "operations": [ Operation ] }`
(последние 50 операций). Карта, которой нет в системе, создаётся с балансом 100 —
это учебное допущение mock, в бою неизвестная карта → 404.

### `POST /api/v1/accrue` — начисление

```json
{ "operation_id": "OP-SHOP-1042", "card": "CARD-77", "points": 12.5,
  "reason": "Бонус за заказ SHOP-1042", "occurred_at": "2026-11-17T09:12:00Z" }
```

Ответ: `{ "operationId", "card", "type": "accrue", "points", "reason", "occurredAt",
"duplicate": false, "balance": float }`.

Повтор с тем же `operation_id` → тот же ответ и `"duplicate": true`.

### `POST /api/v1/redeem` — списание

Тело то же. Ошибки:

| Код | HTTP | Когда | Действие RIH |
|---|---|---|---|
| `DUPLICATE_OPERATION` | 200 | повтор ключа | принять результат |
| `VALIDATION_FAILED` | 422 | баллов меньше, чем списывается | не повторять, сообщить пользователю |

### `POST /api/v1/reverse?operation_id=...` — сторно

Ответ: `{ "status": "reversed", "operationId": ..., "balance": float }`.

| Код | HTTP | Когда | Действие RIH |
|---|---|---|---|
| `NOT_FOUND` | 404 | операции с таким id нет | проверить журнал, не повторять вслепую |
| `CONFLICT` | 409 | операция уже сторнирована | остановить повтор, зафиксировать в журнале |

Сторно — **компенсация** в терминах саги (task_130): возврат чека отменяет
начисление, а не создаёт «отрицательное начисление».

## Что проверяют контрактные тесты

`tests/contract/` и `tests/integration/test_partner_chain.py`:

1. начисление → баланс вырос ровно на `points`;
2. повтор → баланс не изменился, `duplicate: true`;
3. списание сверх баланса → 422, баланс не изменился;
4. сторно начисления → баланс вернулся к исходному;
5. повторное сторно → 409, баланс не изменился;
6. `error500` → клиент ставит операцию в очередь, данные не потеряны.

## Режимы сбоев

`X-Fault-Mode` (или `?fault=`): `ok`, `error500`, `timeout` (35 с), `slow` (4 с),
`rate429` (+ `Retry-After: 5`), `garbage`. Поддерживаются всеми методами выше —
нужны для негативной ветки (task_302) и сценариев деградации.

## Деградация

Лояльность недоступна → заказ проводится, бонусы уходят в очередь отложенных
операций, пользователь видит пометку «бонусы будут начислены позже» (task_131).
Заказ без бонусов — приемлемо; заказ, потерянный из-за бонусов, — инцидент.
