# Единый формат ошибок RIH API (task_82)

Любой ответ ошибки любого маршрута RIH:

```json
{
  "code": "RIH-422",
  "message": "Заказ не проходит валидацию",
  "details": ["заказ без строк"],
  "incidentId": "1874741b-…",
  "timestamp": "2026-11-17T12:00:00Z"
}
```

Клиент принимает решения по `code` (не по тексту), человек ищет
полный контекст по `incidentId` в журнале интеграций. Стек, ключи и
ПДн в ответ не попадают никогда (стандарт §5/§7, task_50/51).

## Справочник кодов

| Код | HTTP | Когда | Действие клиента |
|---|---|---|---|
| RIH-400 | 400 | Тело не разбирается как JSON | Не повторять, чинить отправителя |
| RIH-401 | 401 | Нет X-Api-Key | Проверить ключ |
| RIH-403 | 403 | Ключ неверен/отозван | Ротация ключа у администратора |
| RIH-404 | 404 | Ресурс не найден | Не повторять |
| RIH-409 | 409 | Конфликт: тот же внешний ид, другой ключ/другой payload | Человек разбирает |
| RIH-422 | 422 | Валидация по контракту не пройдена | Исправить данные по details |
| RIH-429 | 429 | Лимит/блокировка перебора или партнёр ограничил | Ждать Retry-After |
| RIH-500 | 500 | Наша ошибка, инцидент заведён | Повторить позже с тем же ключом идемпотентности |
| RIH-502 | 502 | Партнёр вернул не по контракту (garbage) | Инцидент нам, ретрай по политике |
| RIH-503 | 503 | Мы на обслуживании/деградация | Ждать окна, заказы копятся у отправителя |
| RIH-504 | 504 | Партнёр не ответил за таймаут | Ретрай с ключом идемпотентности |
| RIH-200-DUP | 200 | Повтор приёма: ресурс уже был (duplicate=true) | Считать успехом, дубль не создан |

Версии API живут URL: /api/v1/...; v2 добавляется рядом, v1 не
ломается молча (контракт task_77, версия 1.0.0).
