# Единый формат ошибки (task_82)

Одна форма ошибки во всех сервисах RIH. Польза не эстетическая: клиент может
написать **один** обработчик, а дежурный — найти инцидент по `incidentId` в любом
журнале.

## Форма ответа

```json
{
  "code": "PRODUCT_NOT_FOUND",
  "message": "Товар SKU-99999 не найден в НСИ",
  "details": {
    "sku": "SKU-99999",
    "orderExternalId": "SHOP-1042"
  },
  "incidentId": "0f3c1e5a-6f2b-4c1d-9a17-2b7f0a4c1e55",
  "timestamp": "2026-11-17T09:12:44Z"
}
```

| Поле | Тип | Обязательное | Назначение |
|---|---|---|---|
| `code` | string | да | машиночитаемый код: по нему клиент выбирает ветку обработки |
| `message` | string | да | короткое описание для человека; без стека и внутренних имён |
| `details` | object | нет | контекст: какие поля и значения привели к ошибке |
| `incidentId` | string (UUID) | да | связь с журналом регистрации и логами |
| `timestamp` | string (ISO 8601, UTC) | да | момент фиксации ошибки |

## Правила

1. **`code` — из закрытого справочника ниже.** Новый код добавляется через ADR и
   появляется в документации до релиза.
2. **HTTP-статус и `code` согласованы**: статус говорит «что делать с запросом»,
   код — «что именно случилось».
3. **`message` не содержит** персональных данных, секретов, стеков, имён таблиц СУБД.
4. **`incidentId` обязателен** даже для 400: без него разбор инцидента начинается
   с вопроса «а когда это было?».
5. Ошибка в 1С формируется в `РИХ_ОбщегоНазначения.СтруктураОшибки()` — одно место,
   один формат (task_82, task_51).

## Справочник кодов

| Код | HTTP | Что означает | Действие клиента |
|---|---|---|---|
| `VALIDATION_FAILED` | 400 | тело запроса не прошло проверку схемы | исправить данные, не повторять |
| `UNAUTHORIZED` | 401 | ключ/токен не передан или истёк | обновить учётные данные |
| `FORBIDDEN` | 403 | ключ неверный или нет прав на операцию | не повторять, обратиться к владельцу |
| `NOT_FOUND` | 404 | объект не найден | проверить идентификатор |
| `PRODUCT_NOT_FOUND` | 422 | товар отсутствует в НСИ | не повторять: нужна регистрация товара |
| `COUNTERPARTY_NOT_FOUND` | 422 | контрагент не найден | не повторять, завести карточку |
| `DUPLICATE_OPERATION` | 200 | операция уже выполнена (идемпотентность) | принять результат, не считать ошибкой |
| `CONFLICT` | 409 | состояние не позволяет операцию (например, повторное сторно) | не повторять, разобраться в состоянии |
| `RATE_LIMITED` | 429 | превышен лимит частоты | ждать `Retry-After`, затем повторить |
| `PAYLOAD_TOO_LARGE` | 413 | объём больше согласованного | разбить на части |
| `PARTNER_UNAVAILABLE` | 503 | партнёр недоступен | повтор с экспоненциальной задержкой |
| `PARTNER_TIMEOUT` | 504 | партнёр не ответил за отведённое время | повтор; после N попыток — в DLQ |
| `INTERNAL_ERROR` | 500 | внутренняя ошибка RIH | повтор один раз, затем инцидент |
| `UPSTREAM_UNAVAILABLE` | 502 | nginx не достучался до сервиса | повтор; проверить живость сервиса |

## Что делать клиенту по статусу

| Класс статуса | Повторять? | Комментарий |
|---|---|---|
| 2xx | нет | успех, включая `DUPLICATE_OPERATION` |
| 400, 422 | **нет** | данные неверны: повтор даст ту же ошибку |
| 401, 403 | нет | сначала учётные данные и права |
| 409 | нет | конфликт состояния: нужно вмешательство |
| 408, 429, 5xx, сетевая | да | с задержкой `min(2^n, 30)` с и учётом `Retry-After` |

## Пример на стороне 1С

```bsl
Попытка
    Ответ = Соединение.ВызватьHTTPМетод("POST", Запрос);
    Если Ответ.КодСостояния = 429 Тогда
        Пауза = Число(Ответ.Заголовки.Получить("Retry-After"));
        РИХ_ОбщегоНазначения.ЗапланироватьПовтор(Сообщение, Пауза);
    ИначеЕсли Ответ.КодСостояния >= 400 И Ответ.КодСостояния < 500 Тогда
        РИХ_ОбщегоНазначения.ЗаписатьОшибкуДанных(Ответ);   // в DLQ не уходит
    КонецЕсли;
Исключение
    РИХ_ОбщегоНазначения.ЗаписатьСбойВызова(ОписаниеОшибки());
КонецПопытки;
```
