# Контракт транспортной компании (TK) · task_93

Mock-сервис: `src/mock_tk_api` · порт `8022` · через nginx `/tk/`.
Авторизация: `X-Api-Key` (`MOCK_TK_API_KEY`).

## Особенность партнёра: лимит частоты

Не более **10 запросов в минуту на ключ** (скользящее окно). Превышение → `429`
с заголовком `Retry-After: <секунд>`. Клиент обязан:

1. читать `Retry-After` и ждать указанное время, а не повторять сразу;
2. считать 429 **нормальным** ответом, а не ошибкой партнёра;
3. не расходовать лимит на опрос статуса: пакетный опрос или событие от партнёра
   дешевле, чем 200 запросов в минуту (task_93).

## Методы

### `POST /api/v1/calculate` — расчёт стоимости доставки

```json
{ "city_to": "Брест", "weight_kg": 2.5, "volume_m3": 0.03, "declared_value": 120.0 }
```

Ответ: `{ "price": float, "currency": "BYN", "cityTo": string, "weightKg": float }`.
Ограничения: `weight_kg > 0`, `volume_m3 > 0`, `declared_value ≥ 0` — иначе 422.

### `POST /api/v1/shipments` — заявка на доставку

```json
{ "external_id": "SHOP-1042", "city_to": "Брест", "weight_kg": 2.5, "comment": "..." }
```

Ответ `201`: `{ "shipmentId", "externalId", "status": "created", "cityTo", "weightKg",
"createdAt", "duplicate": false }`.

Идемпотентность — по `external_id`: повтор возвращает существующую заявку и
`"duplicate": true` (новый `shipmentId` не создаётся).

### `GET /api/v1/shipments/{shipment_id}` — статус

Жизненный цикл в mock: `created → in_transit → delivered` (по одному шагу за вызов).
В бою статус меняется событиями; учебный «шаг за вызов» нужен, чтобы тест мог
проверить переходы без ожидания.

### `GET /api/v1/shipments/{shipment_id}/label` — этикетка

Ответ: `{ "shipmentId", "labelFormat": "pdf-stub", ... }`.
Режим сбоя `label_failed` → `503`: **заявка при этом остаётся живой**, этикетка
получается позже (компенсация, task_130).

### `GET /health`

`{ "status": "ok", "service": "mock_tk_api", "rate_limit_per_minute": 10, "shipments": int }`

## Режимы сбоев

`ok`, `error500`, `timeout` (35 с), `slow` (4 с), `garbage` (HTML вместо JSON, 502),
`label_failed` (503 на этикетке). Режима `rate429` нет: 429 здесь возникает
естественно — превышением лимита.

## Таймауты клиента

| Операция | Таймаут | Почему |
|---|---|---|
| `calculate` | 5 с | пользователь ждёт цену в форме |
| `shipments` (создание) | 15 с | запись важна, можно подождать |
| `label` | 20 с | этикетка печатается пакетом |
| опрос статуса | 5 с, не чаще 1 раза в минуту на заявку | бережём лимит |

## Деградация

TK недоступна → цена доставки считается по кешированным тарифам с пометкой
«предварительно», заявка ставится в очередь, пользователь видит срок «уточняется»
(task_131). Продажа без доставки невозможна, поэтому очередь заявок — обязательна.
