# HTTP-сервисы конфигурации RIH · task_79, task_83

Публикация: `http://<host>:8009/hs/rih/v1/...` (1С), наружу — через nginx
(`http://localhost:8080/rih/v1/...`). Авторизация: `X-Api-Key` + роль 1С
(task_81, task_133).

> Это **целевой контракт**: маршруты описаны до реализации, чтобы клиент
> (mock-сервисы, тесты, мобильное приложение) и сервер развивались согласованно.
> Реализация — задания task_79 (первый сервис) и task_83 (приём заказов).

## Маршруты

| Метод | Путь | Назначение | Задание |
|---|---|---|---|
| GET | `/hs/rih/v1/health` | живость конфигурации и версии | task_79 |
| GET | `/hs/rih/v1/catalog/products` | каталог: страница, фильтр по дате изменения | task_91 |
| PUT | `/hs/rih/v1/catalog/stock` | приём остатков из магазина | task_91 |
| POST | `/hs/rih/v1/orders` | приём заказа (создание документа) | task_83 |
| GET | `/hs/rih/v1/orders/{externalId}` | состояние заказа | task_83 |
| PATCH | `/hs/rih/v1/orders/{externalId}/status` | статус из магазина | task_83 |
| DELETE | `/hs/rih/v1/orders/{externalId}` | отмена заказа (сторно) | task_83, task_130 |
| POST | `/hs/rih/v1/queue/incoming` | приём сообщения в очередь (асинхронный вход) | task_110, task_111 |
| GET | `/hs/rih/v1/integrations/journal` | журнал интеграций: фильтр по `correlationId`, периоду, статусу | task_84, task_114 |
| GET | `/hs/rih/v1/metrics` | метрики в формате Prometheus (для экспортёра) | task_114, task_271 |

## Правила

1. **Версия в пути** (`/v1/`). Ломающее изменение — новый маршрут `/v2/`, старый
   живёт до окончания переходного периода (task_82, task_267).
2. **Идемпотентность** для `POST /orders`: заголовок `Idempotency-Key` +
   `externalId` в теле. Повтор не создаёт второй документ.
3. **DELETE не удаляет данные**: заказ помечается отменённым, выполняется сторно
   связанных операций (бонусы, доставка). Физическое удаление запрещено (task_130).
4. **Ошибки** — единый формат `error_format.md`, включая `incidentId`.
5. **Каждый вызов пишется в журнал** `РИХ_ЖурналИнтеграций` (task_84): метод, путь,
   статус, длительность, `correlationId`, размер тела, ошибка.
6. **Тело ≤ 4 МБ**; большие выгрузки — постранично или файлом (task_88).
7. **Сервис не содержит бизнес-логики**: только маршрутизация, валидация схемы и
   вызов общего модуля (стандарт, §2).

## Пример вызова

```bash
curl -s -X POST http://localhost:8080/rih/v1/orders \
  -H "X-Api-Key: $RIH_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"externalId":"SHOP-1042","lines":[{"sku":"SKU-00001","quantity":2,"price":12.5}]}'
```

## Что проверяют тесты

* контрактные — схема запроса/ответа, коды ошибок (`tests/contract/`);
* интеграционные — вызов против поднятой базы (`tests/integration/`);
* сквозные — заказ до витрины (`tests/golden_path/`, `tools/ci/vanessa/features/`).
