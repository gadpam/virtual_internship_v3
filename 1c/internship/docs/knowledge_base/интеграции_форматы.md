# Форматы данных в интеграционных контрактах

Версия: 1.4.0
Владелец: руководитель интеграций
Пересмотрен: 2026-10-25

Единые правила представления данных во всех обменах RIH. Правила обязательны для
внешних контрактов: расхождение форматов — самая частая причина «данные пришли,
но не те».

## Даты

Дата и время передаются в формате ISO 8601 в UTC с явным смещением или суффиксом `Z`:

```
2026-11-17T09:12:44Z
2026-11-17T09:12:44+03:00
```

Правила:

1. **Только ISO 8601.** `17.11.2026`, `11/17/26`, метки времени в секундах без
   пояснения — запрещены: их нельзя прочитать однозначно.
2. **Дата без времени** — для календарных сущностей (дата документа, дата курса
   валют): `2026-11-17`.
3. **Часовой пояс хранится вместе со значением.** Время события в системе-источнике
   и время получения в RIH — разные значения, и оба нужны для разбора.
4. **Локальное время** (`Europe/Minsk`) используется в интерфейсе и отчётах, но не
   в контрактах обмена.
5. Границы периода — включительно для начала и исключительно для конца
   (`[from, to)`), если в контракте не оговорено иное.

## Числа и суммы

1. Суммы — десятичная дробь с двумя знаками после запятой, округление по правилам
   бухгалтерского учёта (от копейки). Передавать сумму строкой, если партнёр
   использует JSON и есть риск потери точности, допустимо только по согласованию.
2. Разделитель — точка. Запятая в `12,50` читается как `1250` в половине систем.
3. Количество товара — дробное для весового товара (три знака), целое для штучного.
4. Валюта передаётся отдельным полем в формате ISO 4217 (`BYN`, `USD`, `EUR`, `RUB`).
   «Сумма без валюты» в обмене не допускается.
5. Процентные величины — в процентах (`5.0`), а не в долях (`0.05`), если контракт
   не оговаривает иное. Смешение этих соглашений даёт ошибку в 100 раз.

## Идентификаторы

| Тип | Формат | Пример |
|---|---|---|
| Внутренний ключ RIH | UUID v4 | `0f3c1e5a-6f2b-4c1d-9a17-2b7f0a4c1e55` |
| Внешний идентификатор | строка партнёра, до 64 символов | `SHOP-1042` |
| Ключ идемпотентности | UUID v4 в заголовке `Idempotency-Key` | `9d1c...` |
| Корреляционный идентификатор | UUID v4, единый для всей цепочки вызовов | `7ab4...` |
| Код инцидента | `incidentId` в ответе об ошибке | UUID v4 |

Правила:

1. Внешний идентификатор не интерпретируется: RIH не разбирает его на части и не
   считает его составным ключом.
2. Ключ идемпотентности уникален для логической операции и **не меняется при повторе**.
3. `correlationId` передаётся во все вызовы цепочки и пишется в журнал — по нему
   восстанавливается путь операции.
4. Идентификаторы не переиспользуются: удалённый объект не освобождает свой код.

## Тексты и кодировка

1. Кодировка — UTF-8 для всех обменов. Для файловых обменов кодировка указывается
   в описании формата.
2. XML — с объявлением `<?xml version="1.0" encoding="UTF-8"?>`; SOAP — с явным
   пространством имён.
3. Управляющие символы и переводы строк внутри значений экранируются.
4. Длина строковых полей ограничивается контрактом; превышение — ошибка валидации,
   а не обрезание значения.

## Именование полей

1. В запросах от 1С к внешним сервисам — `snake_case` (`external_id`, `city_to`).
2. В ответах сервисов RIH — `camelCase` (`externalId`, `cityTo`).
3. Правило фиксируется в контракте и проверяется контрактным тестом: «как удобнее»
   в интеграции стоит часов отладки.
4. Булевы поля — утвердительные (`isPersonalData`, `duplicate`), не отрицательные.

## Версионирование формата

1. Версия — в пути (`/api/v1/`) или в атрибуте схемы для XML.
2. Добавление необязательного поля — совместимое изменение: версия не меняется.
3. Удаление поля, изменение типа или семантики — ломающее изменение: новая версия.
4. Старая версия поддерживается не менее 90 дней после ввода новой; дата отключения
   согласуется с партнёром письменно.

## Пример согласованного сообщения

```json
{
  "externalId": "SHOP-1042",
  "correlationId": "7ab4c1d0-2f3a-4b5c-9d1e-2f3a4b5c6d7e",
  "occurredAt": "2026-11-17T09:12:44Z",
  "amount": 25.00,
  "currency": "BYN",
  "lines": [{ "sku": "SKU-00001", "quantity": 2, "price": 12.50 }],
  "isTest": false
}
```
