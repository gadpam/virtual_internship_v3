# Корпус знаний RIH (task_236)

Версия: 1.0.0

Каталог — источник данных для RAG-поиска AI-сервиса: `KNOWLEDGE_BASE_DIR`
указывает сюда, сервис монтирует его только для чтения. Здесь лежат **правила и
регламенты**, по которым работает холдинг, а не код и не логи.

## Что попадает в корпус

| Тип | Пример | Почему |
|---|---|---|
| Регламенты операций | порядок оформления поступления, перемещения | пользователи спрашивают «как правильно» |
| Правила интеграций | форматы полей, даты, идемпотентность | разработчики ищут точные соглашения |
| Определения метрик | кто владеет «выручкой» и как она считается | споры о цифрах решаются ссылкой на определение |
| Инструкции дежурного | где искать вызов по `correlationId` | скорость разбора инцидента |

## Что в корпус НЕ попадает

* персональные данные клиентов и сотрудников (task_135, task_291);
* секреты, ключи, пароли, строки подключения (task_134);
* операционные данные: остатки, цены, суммы — они устаревают за часы, а ответ
  ассистента со вчерашней ценой опаснее, чем отсутствие ответа;
* черновики и личные заметки: в поиск должно попадать только согласованное;
* то, чего в компании нет: выдуманный регламент порождает галлюцинации
  (task_243) — набор `evaluation/provocative_questions.json` проверяет именно это.

## Требования к документу

1. Имя файла — короткое, по-русски, через подчёркивание: `склад_поступление.md`.
   Имя становится идентификатором документа в цитатах ответа.
2. В первых 20 строках — строка `Версия: N.N.N` (её читает `app/chunking.py`).
   Нет версии — документ считается черновиком (`draft`).
3. Разделы — заголовками `#`/`##`: чанкование ориентируется на них, а цитата в
   ответе показывает раздел.
4. Абзацы — смысловые, не длиннее ~900 символов (`chunk_size` в настройках).
   Один абзац = одна мысль: так фрагмент остаётся понятным вне контекста.
5. Числа, сроки и пороги — только согласованные и с источником (кто утвердил, когда).
6. Дата пересмотра в конце документа: просроченный регламент опаснее отсутствия.

## Состав

| Файл | Тема |
|---|---|
| `склад_поступление.md` | приёмка товара: порядок оформления, расхождения, сроки |
| `склад_перемещение.md` | перемещение между складами: статусы, расхождения, инвентаризация |
| `интеграции_http.md` | подключение нового HTTP-сервиса к обмену |
| `интеграции_форматы.md` | форматы полей в интеграционных контрактах: даты, суммы, идентификаторы |
| `аналитика_метрики.md` | словарь метрик: владельцы, определения, источники |
| `журнал_интеграций.md` | как найти вызов по `correlationId` и разобрать ошибку |

## После изменения корпуса

1. Обновить эталонные вопросы: `src/ai_service/evaluation/golden_questions.json`
   (новый документ без вопроса в эталоне не участвует в метриках).
2. Перестроить индекс: `POST /api/v1/index/rebuild` (task_240).
3. Прогнать оценку: `python3 -m evaluation.run_evaluation` и сравнить с базлайном
   (task_238, task_244).
4. Зафиксировать версию корпуса в отчёте — иначе непонятно, на каких данных
   получены метрики.
