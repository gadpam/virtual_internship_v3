# Файловый обмен прайс-листами поставщиков (task_88)

Рабочая область обмена: сюда поставщик кладёт файл, отсюда регламентное задание
его забирает. Каталог намеренно повторяет то, как устроен реальный обмен по
сетевой папке — вместе со всеми его проблемами: файл, который ещё пишется, битые
строки, два формата у одного поставщика.

## Структура каталога

| Каталог | Назначение | Кто пишет |
|---|---|---|
| `samples/` | эталонные файлы формата и их описания | разработчик |
| `incoming/` | точка входа: файл + control-файл | поставщик / скрипт |
| `archive/` | обработанные файлы: `<имя>.<дата обработки>` | регламентное задание |
| `errors/` | файлы, которые не удалось обработать, + протокол ошибки | регламентное задание |
| `quarantine/` | файлы, ожидающие решения человека (спорные данные) | разработчик / оператор |

Рабочие каталоги (`incoming`, `archive`, `errors`, `quarantine`) в Git не попадают:
это операционная зона. Здесь хранятся только `.gitkeep` и образцы.

## Формат прайс-листа (CSV)

* разделитель — `;`, десятичный разделитель — точка, кодировка UTF-8;
* обязательные поля: `sku`, `name`, `price`, `currency`, `valid_from`;
* необязательные: `supplier_code`, `unit`, `min_quantity`, `valid_to`, `vat_rate`;
* первая строка — заголовок; строки без `sku` считаются ошибкой;
* отрицательная цена — ошибка строки, а не всего файла (частичный успех).

## Контроль целостности

Файл считается готовым к обработке **только при наличии control-файла**:

```
prices_supplier_001_2026-11-17.csv          # данные
prices_supplier_001_2026-11-17.csv.ctl      # служебный файл
```

Содержимое `.ctl`:

```
file=prices_supplier_001_2026-11-17.csv
rows=12
bytes=1043
sha256=...
created_at=2026-11-17T05:58:12Z
```

Почему control-файл, а не «ждать N секунд»:

1. ожидание не защищает от оборванной записи — файл может «не меняться» потому,
   что запись прервалась;
2. control-файл пишется последним, поэтому его появление означает завершение записи;
3. `rows` и `sha256` дают проверяемое доказательство: строки не потерялись,
   содержимое не изменилось в пути;
4. `created_at` позволяет отличить старый файл, который не обработали, от нового.

Альтернатива «размер не менялся N секунд» остаётся как запасной вариант для
поставщиков, которые не умеют писать control-файл: в этом случае порог — 60 секунд,
и файл обрабатывается с пометкой «без подтверждения целостности».

## Порядок обработки

1. Найти в `incoming/` пары «данные + `.ctl`». Файл без `.ctl` не трогать.
2. Проверить `sha256` и `bytes`; при расхождении — в `errors/` с протоколом.
3. Проверить `rows` против фактического числа строк; расхождение — в `errors/`.
4. Прочитать файл в транзакции: либо загружены все валидные строки, либо ничего.
5. Строки с ошибками — в протокол (`errors/<имя>.log`), а не «молча пропущены».
6. Успешно обработанный файл переместить в `archive/` с датой обработки, `.ctl` — туда же.
7. Записать результат в журнал интеграций: имя файла, число строк, ошибки, длительность.

## Обработка ошибок

| Ситуация | Куда файл | Что в протоколе |
|---|---|---|
| нет `.ctl` | остаётся в `incoming/` | ожидание, алерт если старше 24 ч |
| не совпала контрольная сумма | `errors/` | фактическая и ожидаемая суммы |
| строка без `sku` | файл обрабатывается, строка — в протокол | номер строки и содержимое |
| отрицательная цена | строка — в протокол | `sku` и значение |
| неизвестная кодировка | `errors/` | определённая кодировка и что ожидалось |
| файл пустой (0 строк) | `quarantine/` | возможная ошибка поставщика, нужно подтверждение |
| цены обнулились у 90% позиций | `quarantine/` | похоже на сбой выгрузки поставщика |

Правило: **битый файл не портит данные.** Частичная загрузка допустима только для
валидных строк и только с протоколом; загрузка «наполовину» из-за оборванного файла
недопустима.

## Образцы в `samples/`

| Файл | Что демонстрирует |
|---|---|
| `prices_supplier_001_2026-11-17.csv` | корректный прайс-лист, 12 строк |
| `prices_supplier_001_2026-11-17.csv.ctl` | control-файл с фактической суммой и числом строк |
| `prices_supplier_002_broken.csv` | файл с ошибками строк: нет `sku`, отрицательная цена |
| `prices_supplier_002_broken.csv.ctl` | control-файл с **заниженным** числом строк: расхождение должно быть обнаружено |
| `prices_supplier_003_truncated.csv` | обрыв записи: последняя строка не закрыта кавычкой |

## Как прогнать обмен руками

```bash
cd 1c/internship/data/supplier_price
cp samples/prices_supplier_001_2026-11-17.csv* incoming/
# далее — регламентное задание «Загрузка прайс-листа поставщика из каталога» (task_88)
```

Проверка результата: файл ушёл из `incoming/`, появился в `archive/`, цены видны в
регистре сведений `ЦеныНоменклатуры`, в журнале интеграций есть запись об обработке.
