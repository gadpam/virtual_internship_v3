# Configuration/ — стартовый проект 1C:EDT конфигурации Retail Integration Hub (RIH)

Это заготовка проекта, с которой вы начинаете работу в sprint_0/task_0.
Структура соответствует проекту 1C:Enterprise Development Tools (EDT):
исходники конфигурации хранятся текстом, поэтому их можно версионировать в Git,
ревьюить и собирать в CI.

## Состав стартового проекта

```
.project                                  — дескриптор проекта EDT
DT-INF/MANIFEST.MF                        — манифест проекта (версия, имя)
src/Configuration/Configuration.xml       — корень конфигурации: имя, синоним, состав
src/Configuration/Module.bsl              — модуль конфигурации (заготовка)
src/Subsystems/РИХ_ИнтеграционныйХаб/     — единственная подсистема стартовой конфигурации
src/CommonModules/РИХ_ОбщегоНазначения/   — общий модуль с первыми функциями (task_2)
src/CommonModules/РИХ_Дата/               — модуль для работы с датами (task_15)
src/Catalogs/ … src/ExternalReports/      — пустые папки: сюда вы добавляете объекты по заданиям
Docs/CodingStandard.md                    — конвенции проекта (заполняется в task_6, task_10)
```

## Как с этим работать

1. Импортируйте проект в EDT (Файл → Импорт → 1C:Enterprise Development Tools project)
   либо создайте базу из `Rih.cf`, собранного в CI (`internship/tools/ci/build.yml`).
2. Все изменения делайте в этом проекте. Папка `1c/project/` — материалы программы,
   её менять нельзя.
3. Объекты добавляйте через EDT (или Конфигуратор + выгрузка в файлы): правки должны
   попадать в Git текстом.
4. Имена объектов — по `Docs/CodingStandard.md` (префикс подсистемы `РИХ_`).
5. Бинарные артефакты (.cf/.cfu/.dt) кладите в `../build/` — эта папка в .gitignore.

## Если у вас нет EDT

Работайте в Конфигураторе и выгружайте конфигурацию в файлы
(«Конфигурация → Сохранить конфигурацию в файл» + выгрузка в XML/текстовые файлы).
Начиная с task_13 Git-трек предполагает текстовые исходники — без них невозможны
диффы, ревью и CI.

## Правило префиксов

Все объекты подсистемы RIH имеют префикс `РИХ_` (общие модули, обработки, роли,
HTTP-сервисы). Исключения — объекты, которые обязаны называться штатно
(например, при подключении БСП). Правило и его обоснование — в `Docs/CodingStandard.md`.
