# Рабочая документация стажёра

Здесь вы пишете то, что делает вашу работу инженерной: описания выполненных
заданий, размышления, решения (ADR), отчёты, письма. В продуктовой разработке
**незадокументированное решение не существует**: через полгода ни вы, ни коллега
не вспомните, почему обмен сделан через очередь, а не через план обмена.

## Структура

| Каталог | Что кладём | Когда |
|---|---|---|
| `templates/` | шаблоны всех документов | читаем перед написанием |
| `adr/` | записи архитектурных решений | после каждого решения с альтернативами |
| `reports/` | отчёты по заданиям, спринтам, кварталам | в конце задания/спринта |
| `reflections/` | размышления: что получилось, что нет, чему научился | после каждого задания |

## Правила

1. **Имена файлов с номером задания**: `task_091_description.txt`,
   `ADR-0012_очереди_вместо_плана_обмена.md`.
2. **Один документ — одна тема.** Отчёт о задании не смешивается с рефлексией.
3. **Пишите в тот же день.** Документ, написанный через неделю, — художественное
   произведение.
4. **Цифры вместо оценок.** Не «стало быстрее», а «p95 снизился с 4,8 с до 1,2 с
   на 12 000 строк».
5. **Файлы лежат в Git рядом с кодом.** Документация в личной папке не переживает
   увольнение (task_305, bus factor).
