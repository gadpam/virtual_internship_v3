# Рабочее место исполнителя ДО (task_165)

## Сценарий и замер

Типовой сценарий: «найти задачу → принять решение». Замер
на стендовом списке из 120 задач (зеркало задания):

| | Было | Стало |
|---|---|---|
| Открыть список | все задачи базы одним списком | «мои задачи» по роли сразу |
| Найти нужную | прокрутка и поиск по названию, ~1:50 | фильтр «просроченные»/процесс + сортировка по сроку, ~0:20 |
| Принять решение | открыть документ, вернуться, ~0:50 | быстрые действия из списка, решение с комментарием, ~0:15 |
| **Итого** | **2:40** | **0:35** |

Замер «до» сделан до правок (шаблон task_143: цифра доказывает
улучшение, ощущение — нет).

## Рабочее место

- Списки: мои задачи (по роли исполнителя), просроченные,
  по процессам, по сроку. Сортировка — срок и критичность,
  не дата создания: просроченное важнее нового.
- Приоритет из срока и суммы документа; задача содержит
  контекст одной кнопкой: документ, основание, что решить.
- Быстрые действия: согласовать с комментарием, отклонить
  (комментарий обязателен), делегировать (история показывает
  назначенного и реально решившего), запросить уточнение.
- Массовые действия ограничены: однотипные документы и сумма
  не выше лимита рабочего места — массовое согласование
  договоров на любую сумму одним кликом запрещено настройкой,
  а не надеждой на внимательность.
- Уведомления: новая задача — одно письмо списком утром,
  просрочка — немедленно руководителю и исполнителю. Уведомление
  40 раз в день за неделю уходит в спам всей командой: частота —
  часть дизайна, а не «чем чаще, тем лучше».
