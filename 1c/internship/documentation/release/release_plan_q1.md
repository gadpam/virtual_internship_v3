# План обновления конфигурации и базы (task_65, итоги Q1)

## Что обновляем

Версия конфигурации Q1 → версия с реквизитом Номенклатура.ЕдиницаИзмерения
(task_24) и обработчиком `РИХ_Версионирование.ОбработчикОбновления_
ЕдиницыНоменклатуры`: исторические товары без единицы получают «шт».

## Учебное обновление на копии (выполнено на аналоге lab65)

| Шаг | Содержание | Время (аналог) | Проверка после шага |
|---|---|---|---|
| 1 | Снять копию базы (backup) | по регламенту стенда | Копия открывается, COUNT товаров сходится |
| 2 | Поставить новую конфигурацию, обновить конфигурацию БД | по регламенту | Нет ошибок реструктуризации |
| 3 | Обработчик обновления: заполнение единиц | 0.76 мс / 50 товаров аналога | SELECT: без единицы = 0 |
| 4 | Повторный запуск обработчика | 0.39 мс, обновлено 0 | Идемпотентность подтверждена |
| 5 | Дымовой контур (task_53): поступление, перемещение, остатки | сценарий | Числа сценария совпали |

Ответственный за шаги 1–2 — администратор ИБ, 3–5 — разработчик;
на учебном стенде обе роли у стажёра, помечено честно.

## Критерии отката

Откатываемся на копию шага 1, если: реструктуризация завершилась
с ошибками; после шага 3 остались товары без единицы и причина не в
данных; дымовой контур не дал чисел сценария; обработчик упал на
пакете данных (частичное заполнение допустимо — обработчик
идемпотентен, сначала разбираемся, потом решаем: повтор или откат).

## Обновление типовой конфигурации (база для task_287)

Инвентаризация доработок до обновления: что изменено в типовых объектах
и почему (у нас аналог — расширения task_48: доработка живёт отдельно и
переживает обновление). Обновление сначала на копии, регресс дымовым
контуром и расчётом ключевых отчётов, окно обновления — вне рабочего
времени склада. Полная практика — task_287 (Q4).
