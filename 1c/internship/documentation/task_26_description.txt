2. ЧТО СДЕЛАНО (аналог labq, PostgreSQL)
   - LEFT JOIN остатков с ценами: 501 строка; INNER: 500. Разница — товар
     SKU-99999 без цены: внутреннее соединение теряет его молча, а это
     ровно тот товар, который товаровед должен увидеть.
   - Соединение агрегата остатков с минимумами по двум условиям
     (Склад+Номенклатура): 50 пар, уникальных 50 — дублей соединение
     не вносит, пока правая сторона уникальна по ключу соединения.
     Обратный пример: соединение с историей цен без среза размножает
     строки по записям истории (правило в стандарт).
   - Виртуальная таблица напрямую (агрегат по 100 тыс. движений внутри
     запроса): 50.8 мс. Через временную таблицу с индексом: соединение
     после неё — 0.31 мс. Честно: материализацию платим один раз, поэтому
     выигрыш — когда таблицу переиспользуют запросы пакета (task_28/30);
     для одиночного запроса временная таблица не нужна.
   - Правило про виртуальные таблицы записано в CodingStandard.md §3.
