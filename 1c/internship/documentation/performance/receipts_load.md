# Нагрузочный тест приёма чеков (task_117)

Дата: 2026-11-17. Контур: зеркало `src/scripts/checks_receipts.py`
(приёмная логика `РИХ_Чеки` и транспорт `РИХ_Кассы` один в один).

## Методика

- Объём по заданию: 100 касс × 1 чек в минуту × 12 часов = 72 000 чеков.
- Каждый чек: одна строка, количество 2, цена 50.00, сумма 100.00;
  ФН уникален на кассу, номера чеков — последовательность внутри ФН.
- Прогон ускоренный: чеки генерируются и принимаются в одном процессе,
  без сети и ожидания минут; меряется именно приёмная логика
  (валидация, ключ идемпотентности, обороты), а не расписание касс.
- Среда: Python 3.11.2, один поток, таблицы приёма — словари по ключу
  (ФН, номер чека) — аналог индекса документа «Чек» по этой паре.

## Результаты

| Проверка | Результат |
|---|---|
| Пакет 100 чеков | принято 96, дублей 3, карантин 1 (расхождение суммы) |
| Повтор пачки после обрыва связи | 10 из 10 — дубли, выручка не изменилась |
| Тот же номер на другом ФН | принят как другой чек |
| Повтор ключа с другим содержимым | карантин: «повтор с другим содержимым» |
| Возврат без исходного / сверх остатка | карантин с причиной в обоих случаях |
| Нагрузка 72 000 чеков | 0.35 с, 208 423 чеков/с, ошибок 0 |
| Обороты нагрузки | сумма 7 200 000.00, количество 144 000, документов 72 000 |
| ZIP пачки из 100 чеков | 20 506 → 599 байт; лимит тела 10 485 760 байт до парсинга |

## Выводы

- Приёмная логика на объёме дня сети работает с запасом на порядки:
  узким местом боевого контура будет запись документов и проведение
  в ИБ, а не валидация; поэтому приём проектируется асинхронно
  (приняли быстро — разобрали очередью, task_110), а ошибки уходят
  в карантин, а не в отказ пакета.
- Проверка «пакет без индексов» из задания закрыта ключом (ФН, номер):
  поиск дубля — O(1) по словарю зеркала и индекс пары в документе
  «Чек»; нагрузка на пустых таблицах не мерялась как сценарий.
- Открытое ограничение среды: дистрибутива платформы нет, поэтому
  цифры — зеркало приёмной логики. Точка возврата: тот же генератор
  пачек против опубликованного `/hs/pos/receipts/batch` в ИБ, замер
  записи документов «Чек» пакетами и проведения по «Продажам».
