# Нагрузочное тестирование интеграций Q2 (task_143)

Генератор — внешний Python (`checks_load.py`), не изнутри системы;
конфигурация стенда зафиксирована: моки — однопроцессные uvicorn
учебного стенда на одной машине с генератором, данные — фикстуры
task_139. Цифры стенда — нижняя граница боевого контура и база
сравнения между спринтами, а не обещание продакшена.

## Целевая нагрузка из требований

| Сценарий | Цель | Основание |
|---|---|---|
| Приём заказов | 2000/час (0.56 запр/с) | пик онлайн-магазина, чёрная пятница ×3 от среднего |
| Выгрузка каталога | 10 000/час (2.78 запр/с) | витрины и партнёрские синки |
| Начисления лояльности | 5000/час (1.39 запр/с) | чеки пикового часа |

## Деградация и точка отказа

Ошибок не появилось ни на одной ступени до параллели 40:
точка отказа по ошибкам на стенде не достигнута — и это честный
результат, а не «система бесконечна». Деградация видна раньше
по хвосту: пропускная способность выходит на плато (~1200–1400
заказы/каталог, ~2300 лояльность) уже к параллели 5–10, дальше
параллель покупает только ожидание: p95 растёт линейно (1 → 34 мс
у заказов к параллели 40). Первое кончившееся звено — один
процесс мока на одной машине с генератором; генератор и сервис
делят CPU, поэтому плато — совместное. Боевой контур упирается
не сюда: его слабые звенья по цепочке — проведение в ИБ
(task_121: ×4.5 под аналитикой) и партнёрские лимиты (ТК 10/мин),
они и станут точкой отказа раньше HTTP-приёма.

## Задачи из отчёта (backlog_q2, LOAD-*)

| ID | Задача | Ожидаемый эффект |
|---|---|---|
| LOAD-1 | Пакетный приём заказов пачками вместо поштучных (контракт уже есть — task_83 batch) | приём пика пачкой снимает N round-trip: ожидаемо ×3–5 к поштучному на том же контуре |
| LOAD-2 | Кэш каталога с инвалидацией по changedAfter для выгрузки | повторные синки не читают СУБД: p95 каталога к уровню кэша (~1 мс стенда) |
| LOAD-3 | Нагрузочный прогон на раздельных машинах (генератор ≠ сервис) при появлении стенда | плато перестанет быть совместным: цифра станет обещанием контура, а не машины |
| LOAD-4 | Алерт на рост p95 интеграций раньше ошибок (порог из этого отчёта) | деградация видна по хвосту за минуты до точки отказа (task_138) |
