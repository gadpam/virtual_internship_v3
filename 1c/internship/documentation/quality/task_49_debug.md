# Отладка в 1С: 10 приёмов (task_49)

Честная рамка: живого отладчика платформы в среде прохождения нет;
приёмы зафиксированы по документации платформы и проверены на зеркальных
разборах кода (пошаговое чтение значений — аналог watch).

1. **Точка останова по условию**, а не «на каждой строке»: останавливаемся
   только для нужного документа/товара.
2. **Выражение-watch вместо Сообщить()**: смотрим значения, не меняя код.
3. **Выполнить до курсора** по уже понятным участкам — не шагаем по библиотекам.
4. **Стек вызовов важнее точки**: половина багов — «кто вообще сюда пришёл».
5. **Отладка серверного вызова из формы**: отладчик подключается к серверу
   ИБ, клиентская точка в &НаСервере без этого не сработает.
6. **Фоновое задание отлаживается отдельным пунктом отладки** (фоновые
   задания в предметах отладки), иначе задание «не останавливается» —
   потому что выполняется не тем процессом.
7. **Сначала воспроизвести без отладчика** (вход → симптом), отладчик —
   для диагноза, а не для поиска «где-нибудь упало».
8. **Граничные ветки отлаживаются парами**: кейс, который работает,
   и соседний, который падает (у нас: Z против .500+03:00).
9. **Не отлаживать на боевой ИБ**: копия базы, тестовый пользователь;
   отладочная остановка проведения блокирует живых людей (task_45).
10. **Найденный баг сначала становится падающим тестом**, потом исправлением
    (регрессия в каркас task_52).

## Три контекста: чем отладка различается

| Контекст | Процесс | Особенность |
|---|---|---|
| Клиент формы | тонкий клиент | видны элементы формы, нет данных ИБ |
| Серверный вызов | сервер 1С | нужен подключённый к серверу отладчик; видна транзакция |
| Фоновое задание | отдельный сеанс задания | свой предмет отладки, свой пользователь и параметры сеанса |

## Найденная ошибка (task_17, разбор ISO)

Симптом: РазобратьIso8601 бросал «Некорректное смещение» на валидной
строке `2026-01-31T21:00:00.500+03:00`. Диагноз по шагам: Остаток после
секунд — `.500+03:00`; код ждал первым символом `+`/`-`/`Z`. Исправление:
дробная часть отрезается сканированием до знака зоны; кейс добавлен
в проверки, в каркас уедет регрессией (task_52).
