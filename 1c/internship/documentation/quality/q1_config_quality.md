## Анализ использования: 28 экспортных методов без вызовов в коде

Разбор показал: это не мёртвый код, а точки входа, которых статический
поиск по `.bsl` не видит. Классификация (10 замечаний):

| # | Замечание анализа | Решение |
|---|---|---|
| 1 | ЗагрузитьПрайсыПоставщиков «не вызывается» | Отклонено: метод назван строкой в ScheduledTask (methodName) |
| 2 | СдвинутьГраницуПоследовательности «не вызывается» | Отклонено: то же, задание ДвижениеГраницы |
| 3 | Подписка расширения ПередЗаписью «не вызывается» | Отклонено: вызывается платформой по подписке |
| 4 | СведенияОВнешнейОбработке/ПечатнаяФормаДокумента | Отклонено: контракт внешних обработок БСП |
| 5 | ВыполнитьТесты и диспетчер каркаса | Отклонено: точка входа обработки РИХ_ЮнитТесты |
| 6 | РИХ_Дата (ВУниверсальную, ГраницыПериода…) | Отклонено: публичный API дат для обменов и отчётов |
| 7 | РИХ_Логирование.ЗаписатьСобытие/КороткоеСообщение | Отклонено: публичный API журналов для вызывающего кода |
| 8 | РИХ_Кэш.СброситьКэш не вызывается ниоткуда | **Принято**: писатель порогов обязан вызывать; точка вызова зафиксирована в документации модуля, живой вызов — при появлении формы записи (backlog) |
| 9 | СформироватьОстатки не виден из .bsl | Отклонено: внешний набор данных СКД-отчёта (строка в схеме) |
| 10 | ПересчитатьШард «не вызывается» | Отклонено: имя метода передаётся ФоновымЗаданиям строкой |

БСП-контракты) — голый поиск по коду даёт 28 ложных срабатываний из 28.
