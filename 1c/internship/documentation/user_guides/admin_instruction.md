# Инструкция администратора стенда RIH (task_66)

## Наполнить тестовые данные

- Номенклатура: обработка «Загрузка номенклатуры из файла», файл —
  `internship/data/nomenclature_sample.csv` (эталон) или сгенерированная
  тысяча `nomenclature_1000.csv`. Повторная загрузка идемпотентна по
  артикулу (обновление, а не дубли).
- Объёмы для производительности: обработка РИХ_ГенераторДанных
  (профиль: склады/товары/документы/строк — task_55) пакетами по 1000.
- Пороги минимальных остатков: регистр МинимальныеОстатки; после
  изменения — РИХ_Кэш.СброситьКэш, иначе отчёты увидят порог к вечеру.

## Где смотреть логи

- События конфигурации: журнал регистрации, отбор по префиксу событий
  «РИХ.» (ошибки, загрузки, пакеты, обновления) — события в JSON,
  инциденты ищутся по ID из сообщения пользователю (task_50/51).
- Обмены файлами: РС ЖурналОбменов (файл, попытка, статус, ошибка).
- Производительность: РС ЗамерыПроизводительности и базлайн
  documentation/perf/baseline_q1_end.md; ТЖ платформы — конфигурация
  documentation/performance/logcfg_example.xml.

## Регламентные задания

ЗагрузкаПрайсаПоставщика — каждые 30 минут, каталог incoming/;
ДвижениеГраницыУчётаТоваров — каждый час. Параллельный запуск загрузки
прагйса запрещён блокировкой внутри метода: второй запуск — не ошибка,
а зафиксированный пропуск.
