# Регламент выполнения скриптов обработки данных (task_183)

Скрипт обработки данных — мини-релиз, а не «запустил SQL».

## Анатомия (обязательна вся)

1. **Предусловия**: SELECT с тем же предикатом, что изменение;
   счёт строк сверяет человек-владелец данных, а не автор скрипта.
2. **Dry run**: тот же скрипт режимом «только показать» — план
   изменений цифрой до боевого запуска.
3. **Архив «до»**: затронутые строки таблицей рядом; откат после
   фиксации — из архива точечно. «У нас есть бэкап» — не откат,
   а восстановление всей базы с потерей чужих изменений дня.
4. **Транзакция** с подсчётом: затронуто ≠ ожидалось — откат
   и разбор, а не «ну почти». Объёмные скрипты — пакетами:
   час в одной транзакции — час блокировок (task_57).
5. **Журнал выполнения**: кто, когда, скрипт и версия, ожидалось,
   затронуто, режим. Скрипт версионируется в репозитории;
   правка с продакшн-копии запрещена.
6. **Идемпотентность**: повторный запуск меняет 0 строк.
   Скрипт «только на один раз» при втором запуске — инцидент.

## Регламент продуктива

- Тестовая копия базы — место первой пробежки, всегда.
- Согласование владельца данных и администратора, окно
  обслуживания, исполнитель и проверяющий — разными людьми.
- Правка SQL-ом в обход платформы — исключение с разрешением
  администратора (целостность task_181), не повседневный путь.
- Проверка результата после: счёт строк и контрольная цифра
  бизнеса, положительная запись в журнале проверки.
