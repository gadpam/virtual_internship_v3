# Уровни изоляции: цена выбора (task_184)

| Уровень | Читатель против писателя | Цена и семантика |
|---|---|---|
| READ COMMITTED | Читатель ждёт зафиксированную запись писателя (в PG — версии строк, ожидание короче) | Ожидания в пиках; каждый оператор видит свежий срез на свой момент |
| SNAPSHOT / RCSI | Читатель читает версии строк из tempdb/хранилища версий и не блокируется писателем | Рост tempdb и версий; «прочитал не то, что уже изменено соседом» — отчёт по срезу, а не по текущему |

Правила дежурного:

- Диагностика — по голове цепочки блокировок: один держатель,
  много ждущих. Ждущий дольше всех — жертва, не виновник.
- «Убить сессию» — последнее средство: откат большой транзакции
  может занять дольше самой транзакции; оценку отката делают
  до убийства, а не после.
- Изоляцию меняет администратор для базы по данным инцидентов,
  а не разработчик «для всех баз компании» по одному утру.
- Взаимоблокировка решается одинаковым порядком доступа
  (task_45): СУБД выбирает жертву, ваша задача — чтобы графа
  ожиданий не возникало.
