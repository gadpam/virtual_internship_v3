# Внешнее соединение с витриной СУБД (task_186)

## Соединение

- Источник: соседняя СУБД, отдельная схема `external_vitrine`,
  таблица-витрина `showcase(sku, external_revenue)`.
- Доступ: только чтение, только перечисленные таблицы,
  отдельная сервисная учётная запись без прав записи.
- Потребитель: отчёт, внешняя витрина — дополнительный набор
  к локальным продажам (соединение по SKU).
- Таймаут запроса 2 с; недоступность — деградация в локальный
  снимок с подписью «данные на 07:00», а не зависание отчёта.
- Canary-контроль схемы по расписанию: ожидаемые колонки сверяются
  до пользователей; переименование ловит мониторинг, а не отчёт
  в понедельник (task_140). Запись в реестр интеграций обязательна.

## Риски

| Риск | Кто отвечает | Как узнаём |
|---|---|---|
| Чужая схема изменилась без релиза потребителя | Владелец внешней схемы | Canary расхождения колонок, алерт до открытия отчёта |
| Источник недоступен или медленный | Администратор соседней СУБД | Таймаут, доля деградаций на снимок, алерт |
| Снимок устарел и принят за живые данные | Владелец отчёта | Время снимка в шапке отчёта обязательно |
| Сервисная учётка получила лишние права | Администратор доступа | Аудит прав только SELECT на перечисленные таблицы |

## Правило проекта

Внешнее соединение допустимо, когда одновременно: данные
справочные/витринные, нужна свежесть «на сейчас», владелец схемы
известен и стабилен, доступ только на чтение по перечню таблиц,
есть таймаут, canary и деградация на снимок, зависимость внесена
в реестр интеграций и ландшафт (task_277).

Обмен обязателен, когда: данные транзакционные, нужна запись,
гарантии доставки/повторов/версий сообщений, источник не должен
влиять на доступность отчёта или чужая схема меняется независимо
и часто. Запись в чужую базу из 1С без явного соглашения
запрещена в любом случае: чужая целостность — чужие правила.
