# КД 2.0 недоступна: что правила делали бы за нас (task_98)

Дистрибутив «Конвертации данных 2.0» распространяется через ИТС и в
среде стенда отсутствует. Шаги задания выполнены универсальным обменом
XML вручную (модуль РИХ_ОбменДанными); здесь записано соответствие,
чтобы при появлении КД правила переносились один в один.

## Соответствие ручного кода правилам КД

| Наш код | Правило КД 2.0 | Что КД сделала бы сама |
|---|---|---|
| ВыгрузитьНоменклатуруXML(ПериодС, ПериодПо) | ПВД «Номенклатура за период» | Отбор по регистрации изменений плана обмена и периоду |
| Атрибуты Ид/Артикул/Наименование пакета | ПКО «Номенклатура» с ПКС по реквизитам | Сериализацию объекта и ссылок по правилам конвертации свойств |
| НайтиТоварПриёмника: Ид → артикул → создать | Поиск приёмника в ПКО: по идентификатору, затем по полям поиска (артикул) | Ту же цепочку, заданную флажками ПКО, а не кодом |
| Итог НайденоПоИд/ПоАртикулу/Создано | Протокол обмена КД | Статистику загрузки из коробки |

## Ограничения подхода (что КД 2 умеет неудобно или не умеет)

1. Правила — XML в отдельной конфигурации: diff и ревью в git почти
   нечитаемы, в отличие от нашего кода в репозитории.
2. Отладка правил — через выгрузку/загрузку файлов и протокол;
   точки останова в привычном смысле нет.
3. Сложные преобразования (не «поле в поле») всё равно пишутся
   обработчиками на встроенном языке — выигрыш КД тает.
4. Версионирование правил между узлами: приёмник на старых правилах
   молча теряет новые реквизиты источника.
5. Производительность: универсальный XML медленнее прямого обмена
   пакетами task_117 на больших объёмах.

Правило проекта по итогам: КД 2 — для разовых миграций и типовых
конфигураций с готовыми правилами; регулярные обмены контура — свой
код (task_102 сравнивает с КД 3).
