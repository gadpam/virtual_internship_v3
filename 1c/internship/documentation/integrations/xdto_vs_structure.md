# XDTO против «структура + ручная сборка» (task_80)

| Критерий | XDTO (РИХ_XDTO, пакет РИХ_Обмен_1) | Структура + РИХ_Форматы |
|---|---|---|
| Надёжность | Схема проверяет тип на границе: битый пакет падает при чтении фабрикой | Валидацию пишет разработчик вручную; забытое поле = тихий Null дальше |
| Документирование | Типы пакета и есть документация, совпадает с OpenAPI | Контракт живёт отдельным документом и расходится |
| Скорость разработки | Медленнее на старте: пакет, типы, версии | Быстрее: структура собирается в одном месте |
| Производительность | Фабрика тяжелее ручного разбора на больших пакетах | Легче; на наших объёмах разница не измерялась как значимая |
| Изменения контракта | Новая версия пакета, старая читается рядом | Тихое изменение ключей структуры ломает партнёра молча |

Правило проекта: жёсткие внешние контракты с версиями (заказы, банк,
ЭДО-подобные пакеты) — XDTO; свободные REST-ответы и внутренние вызовы —
структуры РИХ_Форматы. Мусорный JSON ловится на обоих путях: XDTO —
фабрикой, структуры — валидацией ОшибкиЗаказа до бизнес-логики
(проверено: мусор и пустые строки дают 422).
