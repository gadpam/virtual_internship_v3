# SOAP против REST в RIH (task_85)

| Критерий | SOAP (РИХ_ОбменSOAP, банк) | REST (РИХ_Обмен, магазин) |
|---|---|---|
| Контракт | WSDL + XDTO: схема проверяется машиной до вызова | OpenAPI: схема есть, но проверяется тестами, не транспортом |
| Ошибки | Fault с кодом внутри конверта, HTTP почти всегда 200 | HTTP-статусы + единый формат тела |
| Типизация | Жёсткая: типы пакета версионируются пространством имён | Свободнее: JSON терпит добавление полей |
| Инструменты партнёра | Банк и типовые базы умеют из коробки | Магазин/лояльность/ТК — нативный стек веба |
| Отладка человеком | Конверт XML: видно в Wireshark, тяжело читать глазами | curl и браузер, читается сразу |
| Стоимость изменения | Новая версия сервиса при смене типов | Новое поле обычно не ломает старых клиентов |

Правило выбора RIH: SOAP — где партнёр иначе не умеет (банк, типовые
конфигурации) и где жёсткая схема важнее гибкости; REST — все веб-
партнёры и наши публичные контуры. Ошибки в обоих мирах приводим
к кодам RIH-*: транспорт разный, справочник ошибок один (task_82).
