# HTTP и REST в RIH (task_74): методы, статусы, идемпотентность

## Методы и идемпотентность

| Метод | Смысл в RIH | Идемпотентен | Повтор безопасен |
|---|---|---|---|
| GET | Каталог, остатки, заказы — только чтение | да | да |
| POST | Создать заказ, заявку ТК | **нет** | только с Idempotency-Key |
| PUT | Полная замена ресурса (каталог товара целиком) | да | да |
| PATCH | Смена статуса заказа | да (тот же статус) | да |
| DELETE | Отмена/удаление черновика | да | повтор = 404 или тот же ответ по контракту |

## Коды ответов: когда какой в RIH

| Код | Когда | Пример у нас |
|---|---|---|
| 200 | Успешное чтение/изменение | GET /products, PATCH статуса (проверено) |
| 201 | Создан ресурс | POST /orders создал заказ (проверено) |
| 204 | Успешно, тела нет | Удаление черновика (контракт task_77) |
| 400 | Запрос не по контракту на уровне синтаксиса | Битый JSON |
| 401 | Нет ключа/токена | GET /products без X-Api-Key (проверено) |
| 403 | Ключ есть, прав нет | Неверный ключ mock отвечает 403 (проверено) |
| 404 | Ресурса нет | PATCH статуса несуществующего заказа (проверено) |
| 409 | Конфликт состояния | Тот же external_id с другим ключом идемпотентности (проверено) |
| 422 | Синтаксис верен, семантика нет | Заказ без строк (проверено) |
| 429 | Лимит партнёра | Режим mock rate429 с Retry-After (task_93) |
| 500 | Ошибка на нашей стороне | Режим mock error500: не утекает стек наружу |
| 503 | Временно недоступны/деградация | Окно обновления, партнёр на обслуживании |

## Почему повторный POST /orders создаёт дубль и что делать

POST по семантике не идемпотентен: если ответ первого запроса потерялся
(таймаут сети), клиент не знает, создан ли заказ, и повторяет запрос.
Без защиты второй запрос создаёт второй заказ — склад резервируется
дважды. Лечение тремя слоями: (1) клиент шлёт Idempotency-Key и
стабильный external_id; (2) сервер хранит ключ приёма: тот же ключ —
тот же ответ без повторного создания (у mock это работает: повтор
вернул duplicate=true и тот же итог); (3) тот же external_id с другим
ключом — не дубль, а конфликт 409 человеку на разбор. Наблюдение по
mock: повторный ответ приходит с кодом 201, хотя честнее 200 (ресурс
не создавался); зафиксировано как замечание к task_77/105, поведение
тела при этом корректно.
