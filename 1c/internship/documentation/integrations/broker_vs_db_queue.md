# Брокер против очереди в базе: сравнение и правило выбора (task_111)

Схема событийного контура: проведение документа → outbox (ОчередьОбмена)
→ HTTP-шлюз → RabbitMQ (exchange `rih.events`, routing key — тип события)
→ потребители (Python queue_consumer стенда) → подтверждение в RIH.
Ack — только после обработки; временная ошибка — nack+requeue,
постоянная — DLQ брокера.

| Критерий | Брокер (RabbitMQ) | Очередь в базе RIH (task_95/110) |
|---|---|---|
| Транзакционность с данными | Нет общей транзакции: нужен outbox-мост | Одна транзакция с бизнес-операцией |
| Масштаб потребителей | Много независимых потребителей одного события | Один контур читает свою очередь |
| Маршрутизация | Exchange/binding/routing key из коробки | Ветка диспетчера в коде |
| Задержка доставки | Миллисекунды | Проход задания: секунды–минута |
| Эксплуатация | Отдельный кластер, мониторинг, обновления | Живёт в базе, бэкапится с ней |
| Гарантии порядка | Внутри очереди — да, между очередями — нет | По приоритету и времени очереди |

Правило RIH: события для внешних и множественных потребителей —
брокер; гарантированная доставка партнёру из транзакции бизнеса —
очередь в базе. Между собой они не спорят: outbox пишет событие,
брокер его разносит.
