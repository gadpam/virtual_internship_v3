# OData в RIH: что проверено и политика использования (task_87)

## Честная граница

Стандартный OData-интерфейс — функция платформы 1С: в нашей среде его
нет, список сущностей и права живьём не показать (точка возврата P1-1).
Семантика операторов разобрана на живом REST-контуре стенда (те же
идеи: страница, отбор, поля, счётчик), а производительность фильтра —
на аналоге в миллион строк.

## Операторы и их смысл

| Оператор | Смысл | Аналог у нас |
|---|---|---|
| $top/$skip | Страница сверху с пропуском | limit/offset каталога (проверено: страница 2 по 3) |
| $filter | Отбор по полям | Отборы запросов; цена — ниже |
| $select | Только нужные поля | DTO ответа: поля фиксированы контрактом |
| $expand | Подтянуть связанные сущности | Соединения запроса; осторожно: N+1 в OData-исполнении |
| $orderby | Сортировка | Стабильная сортировка по коду (пагинация task_79) |
| $count | Счётчик до страницы | total в ответе каталога (50) |

## Замер: $filter по неиндексированному полю, 1 млн строк

- Фильтр по неиндексированному `qty = 5`: Parallel Seq Scan, 65.2 мс.
- Фильтр по индексированной паре (warehouse): Index Only Scan, 9.1 мс.

Вывод: OData не виноват и не спасает: свободный $filter по любому
полю на миллионе — это Seq Scan по запросу каждого клиента.

## Политика RIH

OData допустим: внутренние чтения справочников и регистров небольшим
числом доверенных клиентов, отборы по индексированным полям, лимиты
страниц обязательны. Свой HTTP-сервис нужен: публичным партнёрам
(контракт, идемпотентность, единый формат ошибок), операциям записи
и всему, где отборы нельзя отдавать на откуп клиенту. Доступ OData —
только техническому пользователю «только чтение» с урезанным составом
сущностей (проверка прав — на живой ИБ, P1-1).
