# Размышление по заданию task_021

**Задание:** Документ «Поступление товаров»: табличная часть, проведение
**Дата:** 2026-11-17
**Время:** план 3 ч / факт 2 ч

## Где выполняется расчёт суммы и почему

На клиенте — ради отзывчивости: пользователь изменил количество и сразу
видит сумму, не ждёт сервер. На сервере (ПередЗаписью модуля объекта) —
ради истины: клиентским данным верить нельзя, «подправленная» сумма
не должна уехать в регистры. Правило: UX на клиенте, истина на сервере;
проведение берёт только серверные числа. Базовое количество (с учётом
упаковок) тоже пересчитывается сервером — движения регистра всегда
в базовых единицах.

## Что ещё понял

Проведение атомарно транзакцией платформы: ошибка в середине откатывает
всё, поэтому мой код не ловит ошибки «частично» и не фиксирует ничего
руками. Отмена проведения — это удаление движений регистратора, а не
«компенсирующие записи»: история остатков остаётся честной.

## Ошибка, которую я больше не повторю

В форме списка случайно написал путь данных «Объект.Товари» — метаданные
не проверяются глазами надёжно; такие вещи должен ловить импорт в EDT,
которого пока нет, поэтому перепроверяю пути данных поиском по файлам.
