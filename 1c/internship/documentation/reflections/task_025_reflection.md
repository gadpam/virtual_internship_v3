# Размышление по заданию task_025

**Задание:** Основы языка запросов: выборка, условия, порядок
**Дата:** 2026-11-17
**Время:** план 2 ч / факт 1.5 ч

## Null в запросах 1С на трёх примерах

1. **Сумма игнорирует NULL.** `СУММА(Цена)` по строкам, где у товара нет
   цены (левое соединение не нашло пару), посчитает сумму по остальным,
   а `КОЛИЧЕСТВО(*)` посчитает все строки. Итог «средняя цена»,
   собранный руками из этих двух чисел, будет неверным.
2. **Сравнение с NULL — не Истина и не Ложь.** Условие `Цена = NULL`
   не отберёт ни одной строки; работает только `Цена ЕСТЬ NULL`.
   По той же причине `НЕ В (подзапрос)` ломается, если подзапрос вернул
   хоть один NULL: результат — пустой набор без ошибки. Поэтому
   анти-соединение пишем левым соединением, а не НЕ В.
3. **ЕСТЬNULL — явное значение по умолчанию.** `ЕСТЬNULL(Цены.Цена, 0)`
   превращает «цены нет» в 0 там, где отчёт обязан показать число,
   и оставляет NULL заметным там, где отсутствие цены — сигнал.
   Подменять молча везде — значит спрятать товары без цен от товароведа.

## Что ещё понял

В ИЕРАРХИИ — отдельное условие, а не равенство ссылке на группу:
равенство находит только товары самой группы без вложенных.
Виртуальной таблице период и отборы дают параметрами в скобках —
платформа применяет их до чтения, а не после.

## Ошибка, которую я больше не повторю

Использовать «НЕ В» для анти-соединения: NULL в подзапросе обнуляет
результат молча — самая тихая из возможных ошибок запроса.
