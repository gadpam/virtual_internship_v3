## Конфигуратор vs EDT (где что делать)

| Операция | Где | Почему |
|---|---|---|
| Разработка своей конфигурации RIH | EDT | текстовые исходники, диффы для Git, валидация до запуска |
| Ревью правки модуля | EDT/Git | коммит «4 строки в Module.bsl» читается за минуту; .cf — никак |
| Сравнение/объединение с типовой конфигурацией вендора | Конфигуратор | точечно принять объекты вендора, не затирая доработки |
| Сохранить/загрузить .cf, выгрузить .dt | Конфигуратор | бинарные форматы — его родная территория |
| Отладка с остановками и «Выражения» | Конфигуратор (или отладка EDT) | где удобнее; результат вызова ПроверитьОкружение() смотрят здесь |
| Административные операции с ИБ (пользователи, журналы) | Конфигуратор | работает напрямую с базой |
| Переименование объекта/метода с обновлением ссылок | EDT | рефакторинг правит обращения в коде и метаданных |
| Сборка .cf для релиза | CI из EDT-проекта | .cf — артефакт сборки, а не источник истины; живёт в build/ вне Git |
