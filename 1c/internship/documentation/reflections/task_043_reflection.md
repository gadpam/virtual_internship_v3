# Размышление по заданию task_043

**Задание:** Обработчики проведения: где живёт бизнес-логика
**Дата:** 2026-11-17
**Время:** план 3 ч / факт 2 ч

## Что понял

Бизнес-логика проведения живёт в общем модуле, потому что проводит не
только пользователь из формы: тот же документ придёт обменом ночью,
и у него «формы» не будет. Модуль объекта документа — тонкий адаптер
(вызвал общий модуль), форма — интерфейс. Контроль остатков честен
только внутри транзакции проведения и с уменьшением остатка внутри
самого расчёта: две строки по 6 при остатке 10 — превышение, которое
по-строчный контроль без памяти пропустил бы.

## Ошибка, которую я больше не повторю

Проверять остаток отдельным запросом «перед проведением вообще»:
между проверкой и записью другой сеанс уводит товар (гонка task_45).
Контроль — часть проведения, а не ритуал перед ним.
