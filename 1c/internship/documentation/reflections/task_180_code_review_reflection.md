# Размышление по заданию task_180_code_review (ревью sprint_30)

**Задание:** Код-ревью спринта «Сложная отчётность: кросс-системные и управленческие отчёты»
**Дата:** 2026-11-17
**Время:** план 3 ч / факт 1 ч

## Три главных вывода о своём коде за спринт

1. **Отчётность доказывается сверками, а не видом.** Декартово
   раздувание, прочерк плана и файл=экран — критерии цифрами;
   отчёт, который «выглядит правильно», не принят.
2. **Вокруг каждого файла есть процесс.** Внешний артефакт —
   реестр, ревью, прогон и откат; рассылка — журнал по людям;
   допреквизит — цепочка видимости до обмена.
3. **Требования дешевле кода.** Две правки формы закрыты
   прототипом на выдуманных числах до первого запроса —
   самая дешёвая разработка спринта случилась на бумаге.

## Главная причина расхождения плана с фактом

План 20 ч против факта 8.5 ч: спринт — композиция витрин,
словаря метрик и механизмов прошлых кварталов; новыми были
только регламенты вокруг готовых цифр. План заданий по-прежнему
писан под строительство с нуля в пустой конфигурации.

## Честная граница

Платформы 1С, почтового контура и живых внешних баз в среде
нет: формы, СКД-связи и транспорт — точки возврата, поименно
в sprint_30_review.md.
