# Размышление по заданию task_026

**Задание:** Соединения: LEFT, INNER, и почему порядок имеет значение
**Дата:** 2026-11-17
**Время:** план 2 ч / факт 1.5 ч

## Что понял

Внутреннее соединение отвечает на вопрос «у кого есть пара», левое —
«все левые и их пары, если нашлись». Для отчёта «остатки с ценами»
правильный вопрос второй: товар без цены — не отсутствие товара,
а отдельная проблема, которую отчёт обязан показать (501 против 500 строк).
Дубли в соединении рождаются не «от соединения вообще», а когда правая
сторона неуникальна по ключу: история цен без среза размножит товар
по числу записей цен.

## Замер

Виртуальная таблица напрямую: 50.8 мс (агрегат по 100 тыс. движений
внутри запроса). Временная таблица с индексом: соединение — 0.31 мс,
но материализацию платим один раз. Вывод не «временные таблицы всегда
быстрее», а «материализуй, когда результат переиспользуется пакетом».

## Ошибка, которую я больше не повторю

Первая проверка дублей считала повторы пар (склад, товар) в движениях —
а движения и должны повторяться. Дубль — это размножение результата
соединения относительно ожидаемой зернистости, её и надо сверять.
