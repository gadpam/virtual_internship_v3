# Размышление по заданию task_074

**Задание:** HTTP и REST: методы, статусы, идемпотентность
**Дата:** 2026-11-17
**Время:** план 3 ч / факт 1.5 ч

## Что понял

Статус — это контракт, а не настроение обработчика: 401 и 403 у mock
различаются честно (нет ключа — 401, ключ не тот — 403), и клиент по
ним принимает разные решения. Идемпотентность живёт не в методе,
а в ключе приёма: повтор с тем же ключом вернул тот же итог без
дубля, а смена ключа превратила повтор в конфликт 409 — ровно та
семантика, которая нужна приёму заказов.

## Находка по mock

Повторный идемпотентный ответ приходит с 201, хотя ресурс не
создавался; тело (duplicate=true) честное, код — спорный. Не правил:
в mock это задел task_105, а контракт task_77 зафиксирует норму.

## Ошибка, которую я больше не повторю

Считать запрос «успешным» по коду 200 в списке, не проверив тело:
у повторного заказа код и тело рассказывают разные истории.
