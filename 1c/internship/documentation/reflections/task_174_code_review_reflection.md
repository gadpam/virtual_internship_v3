# Размышление по заданию task_174_code_review (ревью sprint_29)

**Задание:** Код-ревью спринта «Бизнес-процессы и задачи в 1С: своя подсистема процессов»
**Дата:** 2026-11-17
**Время:** план 3 ч / факт 1 ч

## Три главных вывода о своём коде за спринт

1. **Процесс — данные переходов, а не формы.** Метрики, сроки
   и узкие места берутся из фактических переходов; процесс,
   живущий в формах, не измеряется и не улучшается.
2. **Каждая механика дисциплины — запрет с кодом ошибки.**
   RIH-PROC-001 (задача без результата) и RIH-PROC-002 (отложить
   без причины) превращают правила в проверяемое поведение.
3. **Владелец поля важнее протокола обмена.** Интеграция
   процессов с трекером держится таблицей истины; синхронизация
   «всего» запрещена решением, а не отсутствием времени.

## Главная причина расхождения плана с фактом

План 18 ч против факта 7.5 ч: спринт целиком собран композицией
готовых механизмов — правила данными (task_153), витрины
(task_121), рабочие места (task_165), идемпотентность (task_105),
живой мок трекера из коробки стенда. План писан под изобретение.

## Честная граница

Платформы 1С в среде нет: формы процессов, адресация и регламент
в ИБ — точки возврата первой базы, поименно в sprint_29_review.md.
