# Размышление по заданию task_124

**Задание:** Выгрузка данных: файлы, таблицы СУБД, потоковая передача
**Дата:** 2026-11-17
**Время:** план 3 ч / факт 1.5 ч

## Что понял

У способов выгрузки нет «лучшего» — есть физика получателя: таблица
быстрее всех, но требует доступа к чужой схеме; файл переживает
недоступность, но платит задержкой; поток единственный не хранит
ничего и не даёт доступа внутрь, зато медленнее на объёме. Критична
не скорость, а цена обрыва: контрольная сумма отклоняет файл целиком,
транзакция откатывает запись, курсор теряет максимум одну страницу.

## Ошибка, которую я больше не повторю

Считать контрольную сумму, но проверять её после чтения данных:
обрезанный файл, применённый наполовину, хуже не принятого вовсе —
манифест сверяется первым.
