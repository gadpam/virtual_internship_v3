# Размышление по заданию task_133

**Задание:** Аутентификация сервисов: API-ключи, токены, OAuth2-подобный поток
**Дата:** 2026-11-17
**Время:** план 3 ч / факт 1.5 ч

## Что понял

Разница между ключом и токеном — не формат строки, а управляемость:
у токена есть срок, владелец, роль и кнопка «отозвать сейчас».
Хранение хешей вместо секретов превращает утечку базы из катастрофы
в плановую ротацию. А единая точка проверки ценнее самой криптографии:
забытый маршрут без проверки обесценивает всё остальное, поэтому
проверка живёт в одном месте, через которое проходят все.

## Ошибка, которую я больше не повторю

Раздавать доступ «ключом в коде и навсегда»: такой ключ нельзя
ни отозвать точечно, ни понять, кто им пользуется.
