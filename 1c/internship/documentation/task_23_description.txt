1. ЧТО ТРЕБОВАЛОСЬ
   Перечисление ТипыЦен, периодический РС цен (по регистратору), документ
   установки цен, два запроса «цена на дату», история цен, заднее число.

2. ЧТО СДЕЛАНО
   - Созданы: перечисление ТипыЦен; РС ЦеныНоменклатуры (периодичность
     «день», подчинён регистратору; измерения Номенклатура+Склад+ТипЦены,
     ресурс Цена); документ УстановкаЦен с проведением в регистр;
     отчёт ИсторияИзмененияЦен (источник — сам регистр: период +
     регистратор + цена). Зарегистрированы в Configuration.xml.
   - Два запроса «цена на дату» сравнены на аналоге PostgreSQL (lab23,
     tools/sql/explore/090_task_23_prices.sql): вариант СРЕЗ ПОСЛЕДНИХ
     (аналог DISTINCT ON) — 2.3 мс; явный подзапрос MAX(Период)+соединение —
     4.4 мс; результаты совпали полностью (A=B: true). Объём честно:
     учебная история регистра (~2 тыс. записей после конфликтов PK
     при массовой вставке) — вывод о равенстве надёжен, вывод о времени
     предварительный до объёма task_55.
   - Задним числом: цена на 20.01 до вставки записи 10.01 — 100.00,
     после — 99.00. Ранее проведённые документы при этом не ломаются:
     сумма строки документа хранится в самом документе (ПередЗаписью),
     а не тянется из регистра в момент чтения.
   - Запросы 1С: СРЕЗ ПОСЛЕДНИХ — виртуальная таблица
     РегистрСведений.ЦеныНоменклатуры.СрезПоследних(&Дата, Условия);
     второй вариант — подзапрос МАКСИМУМ(Период) с группировкой по
     измерениям и обратное соединение. В проект принят СрезПоследних
     (короче и не даёт написать рассинхрон условий).
