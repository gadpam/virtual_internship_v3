## Процесс

1. **Формирует** бухгалтер-владелец формы из данных учёта
   (RIH для оперативных форм, бухгалтерская база для налоговых).
2. **Проверяет** предварительный прогон контрольных соотношений
   (отдельный модуль проверок, не форма): отчёт готовности
   показывает непрошедшие соотношения и документы-причины.
3. **Подписывает** главный бухгалтер УКЭП; подписанный отчёт
   хранится парой с протоколом приёма — «вроде отправили»
   без протокола отправкой не считается.
4. **При расхождении** ошибку правят в учёте, а не в форме:
   форма не место, где прячут ошибки данных. Непрошедшее
   соотношение после срока — инцидент с владельцем формы
   (календарь сроков task_119).

Разработчик отвечает за находимость ошибок до отправки,
а не за их отсутствие в учёте: «проверка №4 не прошла, строки
110–130 не дают строку 100» вместо «бухгалтер говорит, неверно».
