# Форма ПРОД-25: отчёт о розничных продажах отраслевому оператору

Задание task_119. Упрощённая учебная форма; оператор и сроки вымышлены,
механика — настоящая: заполнение из учёта, машинные проверки до отправки,
неизменяемые версии, квитанции.

## Состав формы

Данные берутся из документов «Чек» и регистра «Продажи» за период —
отчёт не считается «по особым правилам» в обход учёта.

- Шапка: код формы `ПРОД-25`, версия формата, период (начало/конец),
  момент формирования, количество получателей (магазинов).
- Раздел А (по магазинам): код магазина, продажи, возвраты, чистая
  выручка, чеков продаж, чеков возвратов.
- Раздел Б (итоги холдинга): те же показатели суммой по разделу А.

## Контрольные соотношения (модуль РИХ_ОтраслевыеОтчёты)

Те же проверки применит оператор; у нас они запускаются до отправки.

| Код | Проверка |
|---|---|
| КС-01 | Полнота: каждый магазин строки есть в справочнике складов-магазинов |
| КС-02 | Арифметика строки: чистая выручка = продажи − возвраты |
| КС-03 | Итог: суммы раздела А равны разделу Б по каждому показателю |
| КС-04 | Период шапки совпадает с периодом выгрузки файла |
| КС-05 | Количество получателей заполнено и равно числу строк раздела А |
| КС-06 | Нет отрицательных продаж, возвратов и количеств чеков |
| КС-07 | Возвраты магазина не превышают его продажи за период |

Нарушение любого КС блокирует отправку: файл оператору не уходит,
ошибки видны списком с кодами — тем же языком ответит протокол оператора.

## Версии и квитанции

- Отправленный отчёт неизменяем: объект версии хранит снимок формы,
  файл (JSON) и его SHA-256.
- Корректировка — новый документ: `НомерВерсии + 1`, ссылка
  `ПредыдущаяВерсия`, обязательная причина. Старая версия не правится.
- Статусы: Черновик → Отправлен → Принят («сдано») / Отклонён →
  ТребуетсяКорректировка → новая версия.
- Квитанция оператора (номер, статус, протокол, хеш файла) хранится
  в РС КвитанцииОператора рядом с отчётом, а не скриншотом в папке:
  при споре о штрафе доказательство — пара «файл + квитанция».

## Регламент

- Срок: до 25-го числа месяца, следующего за отчётным (календарь —
  task_113); формирование — не позднее 20-го, чтобы проверки и
  корректировка успели до срока.
- Ответственный: бухгалтер по розничной отчётности; владелец
  инцидента просрочки — руководитель учёта (просрочка — операционный
  инцидент, а не сюрприз).
- При отклонении: в день получения протокола статус переводится
  в «ТребуетсяКорректировка», причина разбирается по кодам КС,
  корректирующая версия отправляется в течение 2 рабочих дней,
  пара «отклонённая версия + протокол» сохраняется для аудита.
