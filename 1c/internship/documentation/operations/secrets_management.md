# Управление секретами (task_134)

## Аудит: где секреты жили и где живут теперь

| Секрет | Было | Стало |
|---|---|---|
| Логин/пароль шлюза банка | литералы в коде клиента 1С | константы контура `РИХ_ЛогинБанка`/`РИХ_ПарольБанка` (значения в ИБ, не в Git) |
| Ключи ТК, магазина, лояльности | константы контуров | без изменений: значения в ИБ, код читает константу в момент вызова |
| Секреты интеграционных клиентов (task_133) | — | только SHA-256 хеши в `КлиентыИнтеграций` |
| Ключи моков стенда | переменные окружения с учебными значениями по умолчанию | без изменений: учебный контур, ключи публичны из README моков и ничего вне стенда не открывают |
| Пароль роли СУБД стенда (bi_reader) | в скрипте доступа витрин | учебный пароль локального стенда; боевой контур получает пароль из хранилища при создании роли |

## Правила

- Секрет живёт вне кода: константа контура (1С), переменная окружения
  или CI-secret (сервисы), локальный `.env` (в `.gitignore`, рядом
  `.env.example` без значений). Код читает секрет в момент
  использования и не логирует его никогда — ни в журнал, ни в ошибки.
- Среды разделены: dev/test/prod — разные наборы секретов; утечка
  dev-секрета не открывает продакшен.
- Секрет, попавший в историю Git, скомпрометирован навсегда:
  лечится только ротацией. Переписывание истории не решение —
  клоны и кэши уже разошлись. Проверка истории сканером: текущих
  боевых форматов в 300 коммитах не найдено (checks_secrets).

## Стража

`src/scripts/scan_secrets.py` + job Security в CI: известные форматы
ключей, присвоения паролей литералами, строки высокой энтропии
у секретов, `.env` в индексе. Отчёт показывает файл и строку, но не
секрет. Учебные ключи стенда — явный allowlist с причиной.
Тестовый боевой секрет стражу зажигает (checks_secrets), коммит
с ним до слияния не доходит.

## Выдача и ротация

- Выдаёт владелец контура (роль из реестра интеграций), передаёт
  по каналу вне репозитория и почты в открытом виде; факт выдачи
  и ротации фиксируется в журнале (task_133: RIH-SECRET-ROTATE).
- Периодичность: планово — раз в квартал; внепланово — при утечке,
  уходе сотрудника с доступом, смене партнёра.
- Ротация без простоя: два активных значения, клиент переключается,
  старое отзывается в конце окна grace (task_133).
- Подтверждение «секрета в Git нет» — вывод сканера и
  `git log -S`, а не слова разработчика.
