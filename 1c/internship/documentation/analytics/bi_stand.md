# BI-стенд: Superset на витринах (task_126)

## Как поднять

```bash
cd 1c/internship/tools
docker compose -f docker-compose.full.yml up -d postgres superset
# http://localhost:8088 — admin / SUPERSET_SECRET_KEY из .env
```

Superset живёт только в полном стенде (`docker-compose.full.yml`),
не в базовом. Подключение — к СУБД витрин, а не к оперативной базе
1С (решение task_121): SQLAlchemy URI
`postgresql+psycopg2://bi_reader:<пароль>@postgres:5432/rih`.
Пользователь `bi_reader` (скрипт `tools/sql/marts/070_bi_access.sql`,
роль создаёт администратор стенда): только схема `marts`, только
чтение. Запись и staging ему закрыты — проверено зеркалом
`checks_bi_stand.py` негативными сценариями.

## Первый дашборд: три вопроса бизнеса

| График | Вопрос | Источник |
|---|---|---|
| Продажи по дням | «мы растем или падаем?» | `marts.v_sales_daily` (revenue по date_key) |
| Топ-10 товаров | «что продаётся?» | `marts.fact_sales` + `dim_product` |
| Остатки по складам | «что доступно к продаже?» | витрина остатков — Q3; панель специфицирована в `tools/bi/dashboards/`, источник ещё не построен |

Поверх каждого дашборда — баннер свежести: `max(loaded_at)` витрины.
Ответ на проверку понимания написан на дашборде, а не в голове:
директор открывает дашборд в 9:00, данные на 7:00 — это **нормально**
по регламенту (итог дня к 06:00, интрадей-дельта ежечасно, task_123);
ненормально — когда баннер старше SLA, и тогда действует регламент
инцидента task_125.

## Регламент обновления

02:00 — полная загрузка витрины (`065_load_fact_sales_daily.sql`,
прогон в `marts.etl_runs`); ежечасно — дельта изменённых дней
(task_123); 06:30 — автосверка (task_125). Дашборд не обновляет
данные сам: он показывает то, что загрузила витрина, и честное
время этой загрузки.

## Кто отвечает

Витрины и загрузка — владелец данных (финансы, M-001); доступы
`bi_reader` — администратор стенда; дашборды — аналитик розницы.
Новая цифра на дашборде — только после записи в словарь метрик
(task_125), а не после удачной панели.

## Открытые ограничения среды

- Контейнер Superset не поднят в рабочем окружении прохождения:
  демона Docker нет. Контракт стенда проверен исполняемо
  (`checks_bi_stand.py`: доступы, три запроса, свежесть); точка
  возврата — `docker compose -f docker-compose.full.yml up -d
  postgres superset` в окружении с Docker, вход admin/…, скриншот
  дашборда в `build/bi/`.
- Панель остатков ждёт витрину остатков Q3: пустой график «для вида»
  не публикуется.
- Русские кварталы — из эталона даты.
