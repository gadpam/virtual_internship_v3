# ADR (task_40): как хранить многоязычные наименования

- **Контекст:** интерфейс RU/EN, товары продаются в двух странах;
  наименование на языке пользователя нужно в формах и отчётах.
- **Варианты:**
  (а) реквизиты-колонки НаименованиеRU/НаименованиеEN в справочнике —
  просто для двух языков, но третий язык = новые метаданные, релиз
  и мигрень во всех запросах («какую колонку читать»);
  (б) регистр сведений Номенклатура×Язык→Наименование — новый язык
  данными, чтение одним запросом по коду языка;
  (в) подчинённый справочник переводов — почти как (б), но тяжелее:
  ссылки, владельцы, формы ради простого текста.
- **Решение:** регистр сведений НаименованияНоменклатуры (вариант б).
  Базовое Наименование справочника остаётся русским и обязательным:
  перевод — дополнение, отсутствие перевода не ломает учёт (отчёт
  показывает базовое с пометкой языка, а не пустоту).
- **Последствия:** чтение наименования на языке — функция
  (Номенклатура, КодЯзыка) с fallback на базовое; переводы заполняются
  отдельной загрузкой; поиск по наименованию ищет по базовому + переводам.
