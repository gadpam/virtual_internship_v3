# Доработка типовой конфигурации: сравнение подходов (task_159)

Иерархия способов: штатные механизмы (дополнительные реквизиты,
механизмы типовой) → внешние отчёты/обработки → расширение →
изменение конфигурации с осознанной ценой. Снятие с поддержки
ради одного реквизита — подпись под вечным ручным обновлением.

| Критерий | Правка конфигурации | Расширение | Внешняя обработка |
|---|---|---|---|
| Поддержка поставщика | снимается | сохраняется | сохраняется |
| Обновление на новый релиз | ручной перенос правок каждый релиз | регрессионная проверка расширения | не зависит от релизов |
| Глубина вмешательства | любая | точки расширения типовой; не всё поддаётся | только свои сценарии, событие документа не перехватить |
| Снимаемость | откат = восстановление бэкапа | снял расширение — основа как была | удалить файл |
| Цена ошибки | убитое обновление в закрытие периода | контроль молча исчез после обновления, если не проверять | функционал недоступен из документа |
| Когда выбирать | механизм недоступен расширению И цена записана | доработка поведения типовых объектов | отчёты, разовые операции, обмены |

Проверка приёмки расширения — по шагам: поставили → провели
документ с новым контролем → обновили основу на следующий
релиз → расширение на месте, контроль работает. Доработка,
проверенная только «документ открылся», приёмку не прошла.
