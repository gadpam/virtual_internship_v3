   Разобрать docker-compose.yml стенда (сервисы, образы, тома, сеть, порты),

2. ЧТО СДЕЛАНО
   - Сервисы основного compose (11) разобраны по назначению — таблица ниже.
     Тома: pg_data (данные СУБД переживают удаление контейнера),
     rabbitmq_data. Сеть: rih_net (внутри сервисы ходят по именам,
     наружу публикуются только заданные порты).
   - Демона Docker в окружении нет, поэтому «одна команда» выполнена
     локальными аналогами: СУБД — локальный PostgreSQL 16.2 (БД rih,
     как pgvector/pgvector:pg16 из compose). Compose-файлы при этом
     проверены статически: YAML всех трёх файлов разбирается, сервисы,
     healthcheck (pg_isready) и обязательный ${POSTGRES_PASSWORD:?}
     на месте — без .env стенд честно не стартует.
   - Параметр через .env: NGINX_HTTP_PORT 8080 → 18080. Compose-файл при
     этом не менялся (git status по нему пуст) — доказывает, что параметр
     живёт в .env, а не в коде окружения.
   - Учебная поломка: сервер СУБД остановлен; подключение честно получило
     отказ («connection to server ... failed: No such file or directory /
     Is the server running»). Именно такую ошибку увидит и 1С: это не
     «сломался Docker», а сервис не поднялся. Сервер запущен обратно,
     SELECT под пользователем rih — «СУБД восстановлена».
   - Версии образов зафиксированы в VERSIONS.md.
