# Требования к отчёту «Продажи по магазинам» (task_180)

Владелец со стороны бизнеса: коммерческий директор. Интервью —
учебное (ментор в роли заказчика; живая встреча — точка возврата,
как task_148): цель отчёта, пользователи, решения, периодичность.

Фильтр каждого требования: «какое решение примете по этой
цифре?» Цифра без решения в отчёт не попадает.

## Требования и критерии приёмки

| ID | Требование | Критерий приёмки |
|---|---|---|
| RPT-1 | Обороты по магазинам за месяц из витрины | совпадают с витриной task_122 до копейки по каждому магазину |
| RPT-2 | Скорость | построение ≤ 5 с на стенде 100 000 чеков |
| RPT-3 | Пустой период | заголовки и нули, ошибки нет |
| RPT-4 | Детализация до групп товаров | drill-down магазин → группа двумя кликами |
| RPT-5 | Возвраты отдельной колонкой по дате возврата | сверка с M-006 словаря метрик |
| RPT-6 | Сравнение с тем же периодом прошлого месяца на рабочих днях | динамика в рабочих днях, не календарной суммой |
| RPT-7 | Магазин без плана | прочерк в план-факте, в процент не входит (M/правило task_177) |
| RPT-8 | Источник и свежесть на экране | подпись «витрина на 06:30» видна без открытия настроек |
| RPT-9 | Выгрузка XLSX тем же файлом, что на экране | цифра файла = цифре экрана до копейки |
| RPT-10 | Права: руководитель видит только свои магазины | проверка вторым пользователем, чужих магазинов нет |

## Прототип (согласован до разработки)

Макет с выдуманными числами: три магазина, выдуманные обороты
1 000 / 2 000 / 3 000, колонки «оборот, возвраты, план, %,
к прошлому периоду». Согласование по структуре, а не по цифрам:
реальные числа на прототипе уводят совещание в выяснение
«почему тут столько», когда обсуждать надо форму отчёта.

Изменения по прототипу: колонка возвратов вынесена из сносок
в таблицу (решение владельца: возвраты смотрят каждую неделю),
сравнение с прошлым периодом оставлено на рабочих днях.

## Приёмка и итерации

Приёмка — чек-лист по RPT-1..10, каждый критерий проверяем
цифрой или действием; «вроде то» приёмкой не является.
Оценка экономии: без прототипа отчёт по продажам historically
делался 4–5 версиями; здесь изменения формы закрыты прототипом
до первого запроса — сэкономлено минимум 2 итерации разработки
(честная оценка по двум правкам прототипа, а не обещание).
