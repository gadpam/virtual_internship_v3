# Архитектурные решения RIH (ADR)

ADR — короткая запись решения, у которого были альтернативы. Формат:
`ADR_Template.md`. Нумерация сквозная, имена файлов:

```
ADR-0001_текстовые_исходники_EDT_вместо_cf_в_Git.md
ADR-0002_обмен_с_магазином_через_очередь.md
```

## Индекс

| № | Решение | Статус | Дата | Задания |
|---|---|---|---|---|
| 0001 | [Пример] Текстовые исходники 1C:EDT в Git вместо `.cf` | принят | 2026-01-10 | task_64 |

> Заполняйте индекс по мере появления решений. ADR без индекса никто не найдёт.

## Когда ADR обязателен

1. Есть две и более жизнеспособные альтернативы.
2. Решение влияет на другие команды или на ландшафт систем.
3. Отмена решения стоит дорого (данные, контракты, инфраструктура).
4. Решение принимается «на вырост» и его обоснование неочевидно.
5. Кто-то из коллег спросил «а почему так?» — значит, нужен ADR.

## Когда ADR не нужен

* выбор имени переменной, цвета оформления, порядка колонок;
* решение, полностью предписанное стандартом (`Docs/CodingStandard.md`);
* временный костыль с датой удаления — достаточно записи в реестре техдолга
  (task_220).

## Правила

* ADR **не редактируется задним числом**: новое решение — новый ADR со статусом
  «заменяет ADR-NNNN».
* У каждого решения есть **условие пересмотра**.
* Статус «предложен» означает, что решение ещё не принято: не начинайте реализацию.
