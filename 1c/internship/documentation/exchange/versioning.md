# Версионирование обменов и регламент обновления (task_104)

## Версия в сообщении

Каждое сообщение обмена несёт `ВерсияФормата` в заголовке пакета.
Приёмник проверяет версию до разбора тела (РИХ_ОбменДанными.
ПроверитьВерсиюПакета): своя и предыдущая — принимаются (предыдущая
конвертируется значениями по умолчанию новых полей), выше своей —
отказ `RIH-422` с обеими цифрами в тексте ошибки.

Отказ, а не «попробовать разобрать»: парсер, почти понявший чужой
формат, калечит данные тихо; громкий отказ чинится регламентом.

## Матрица совместимости

| Источник → Приёмник | v1 | v2 |
|---|---|---|
| Сообщение v1 | принять | принять с конвертацией |
| Сообщение v2 | отказ RIH-422 | принять |
| Сообщение v3 (будущее) | отказ RIH-422 | отказ RIH-422 |

## Сценарий «источник обновился, приёмник ещё нет»

Источник шлёт v3, приёмник понимает до v2: приёмник отвечает
RIH-422 «версия 3 не поддерживается (понимаем 1 и 2)», сообщение
остаётся в очереди источника со статусом ошибки версии, данные не
калечатся. Лечится обновлением приёмника по регламенту ниже;
автоматического «понижения» формата источник не делает — молчаливая
потеря новых полей хуже явной паузы.

## Регламент обновления обменов

1. Изменение формата предлагается правкой OpenAPI/схемы и этого файла
   (матрица обновляется до кода, а не после).
2. Сначала обновляются приёмники (они обязаны понимать N и N−1),
   проверяется приём старой версии на стенде.
3. Через 7 дней обновляются источники; окно — воскресенье 02:00–04:00.
4. Старая версия снимается, когда счётчик принятых сообщений старой
   версии равен нулю 14 дней подряд (контроль task_101/107).
5. Откат: источник возвращается на предыдущую версию флагом контура;
   сообщения, принятые новой версией, не переигрываются.
