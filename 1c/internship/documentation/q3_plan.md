## Окружение: проверено делом, а не «установлено»

| Инструмент | Статус на стенде | Проверка |
|---|---|---|
| PostgreSQL 16.2 (серверная СУБД стенда) | жив, принимает запросы | `SELECT version()` — отвечает |
| Python/Node, зеркальный контур checks_* | работает весь Q2 | 80+ сценариев зелёны |
| MS SQL Server в Docker | недоступен: демона Docker нет | `docker` отсутствует |
| Учебные БП и ДО (ИТС) | недоступны: дистрибутивов и лицензий в окружении нет | зафиксирован запасной план ниже |
| Superset | не поднят (нет Docker) | дашборды Q2 — контрактом BI и витринами PostgreSQL |
| Ресурсы машины | 3.9 ГБ RAM, 2 CPU | честная цифра: БП+ДО+SQL+Superset одновременно не влезут даже при Docker |

### Запасной план (согласован до старта спринта 26, а не в середине)

- Спринты 31–34 (СУБД): PostgreSQL вместо MS SQL — планы запросов
  (EXPLAIN ANALYZE), индексы и статистика концептуально те же;
  специфика MS SQL (DMV, T-SQL) — теорией с точками возврата
  на машину с Docker. Паттерн Q1/Q2 повторяется осознанно.
- Спринты 26–29 (БП/ДО): учётная модель строится в RIH и зеркалах
  PostgreSQL; типовые конфигурации — точками возврата к появлению
  ИТС. Если ИТС не появится к спринту 27, план пересматривается
  на milestone-точке спринта 26, а не «как-нибудь в середине».
- BI (35): витрины и семантика на PostgreSQL (контур task_126
  уже работает так), Superset — при появлении Docker.

## Личный план и контроль

Режим Q2 сохраняется (коэффициент факта 0.43 учитывается:
оценка нового внешнего контура получает шаг «контракт вживую»).
Точки контроля: закрытие каждого спринта ревью с Critical 0;
milestone спринта 26 — пересмотр запасного плана по ИТС;
середина квартала (спринт 32) — сверка часов план/факт.

## 5 рисков квартала

| Риск | Запасной план |
|---|---|
| ИТС/лицензии не появятся весь Q3 | зеркальный контур (выше), точки возврата поименно; пересмотр на спринте 26 |
| Машина 3.9 ГБ не тянет тяжёлые стенды | объёмы профилями генератора; тяжёлое — последовательно, не параллельно |
| MS SQL специфика не проверяется руками | PostgreSQL-концепции + теория DMV/T-SQL с точками возврата |
| Данные закрытия периода окажутся сложнее модели | вопросы аналитику (выше) до кода спринта 26 |
| Оценки снова поплывут на внешних зависимостях | шаг «контракт вживую» в оценке (урок task_141/149) |
