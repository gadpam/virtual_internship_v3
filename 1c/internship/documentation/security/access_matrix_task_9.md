# Матрица прав RIH (task_9) — вход для task_20 и task_24

Объекты «Номенклатура» и «Перемещение товаров» появятся в sprint_4;
матрица проектируется наперёд. Доступ по умолчанию запрещён: что ролью
не разрешено, то запрещено. Итоговый доступ пользователя — объединение ролей.

Легенда: Ч — чтение, З — добавление/изменение, У — удаление, П — проведение,
«—» — права нет. RLS отмечена отдельно.

| Объект | РИХ_Кладовщик | РИХ_Товаровед | РИХ_ИнтеграционныйСервис |
|---|---|---|---|
| Справочник Склады | Ч (RLS: только закреплённые за &ИмяПользователяИБ) | Ч | Ч (все, без RLS) |
| Справочник Номенклатура (sprint_4) | Ч | Ч, З, У | Ч |
| Документ ПеремещениеТоваров (sprint_4) | Ч, З, П (свои склады — RLS по складу-отправителю) | Ч | — |
| Регистр СкладыПользователей | — | — | — (ведёт администратор) |
| Регистр РИХ_ИсторияИзменений | — | Ч | — |
| Запуск клиента, вывод (печать/сохранение) | да | да | да (вывод — нет: сервису некуда выводить; оставлено для отладки интеграций) |

Принципы:
- наименьшие привилегии: роль даёт ровно то, что нужно для работы;
- «Полные права» — только администратор, не рабочие и не сервисные роли;
- сервис не получает запись в учётные объекты: чтение справочников —
  максимум (компрометация сервиса не должна давать запись в базу);
- RLS проверяется реальными пользователями, а не администратором:
  у администратора список всегда полный, и такая проверка ничего не доказывает.
