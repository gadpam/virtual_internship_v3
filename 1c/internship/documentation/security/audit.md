# Аудит доступа и изменений (task_137)

## Что пишется и зачем

Журнал регистрации платформы — база; аудит — осмысленная выборка
событий из РС `АудитДоступа`, куда механизмы пишут сами через
`РИХ_Аудит`:

| Событие | Кто пишет | Что фиксируется |
|---|---|---|
| `pdn_view` | показ телефона по роли ПДн (task_135) | кто, какого клиента, основание роли |
| `pdn_erasure` | обезличивание субъекта | кто, клиент, «по запросу субъекта» |
| `settings_change` | изменение настроек интеграций | было → стало, основание (номер задачи) |
| `exchange_stop` / `exchange_start` | остановка и запуск обменов | кто, обмен, основание |
| `secret_rotate` | ротация секрета клиента (task_133) | кто, клиент, окно grace; сам секрет — никогда |
| `rights_change` | изменения прав и ролей | кто, кому, что выдано/отозвано |

Аудитируется чувствительное, а не всё подряд: аудит всего тонет
объёмом, и нужное событие ищут часами — аудита на деле нет.

## Отчёты вместо фильтра по миллиону

- «Действия пользователя за период» — хронология одного человека.
- «Доступы к чувствительным данным» — полные показы ПДн
  и обезличивания по людям и объектам.

Оба формируются из `РИХ_Аудит` за минуты; чтение отчётов — роль
безопасности: аудит сам содержит чувствительную картину доступов.

## Учебное расследование

Вопрос: «кто отключил обмен вчера в 18:00?» По аудиту (зеркало
checks_audit): обмен с ТК остановил Иванов И. в 17:58, основание —
задача обновления UPD-221; перед этим он же изменил настройку
расписания («каждые 15 мин» → «остановлен»), в 19:05 обмен запущен
обратно. Ответ — одна выборка по событию и периоду, без перебора
чатов. Тот же отчёт отвечает на «учёткой уволившегося смотрели
ПДн»: событие `pdn_view` покажет пользователя и объект, а событие
увольнения должно было отозвать права в день ухода — связка
`rights_change` делает отсутствие отзыва видимым.

## Хранение и защита

- Оперативный срок — 1 год; дальше `ВыгрузитьВАрхивИОчистить`:
  сначала текст архива (JSON Lines во внешнее хранилище), только
  потом чистка. Порядок задан кодом.
- Регистр append-only для прикладных ролей: записи и чтения только
  у роли безопасности и самих механизмов записи; удаление —
  запрещено правами. Аудит, который можно подчистить, не аудит.
- В записях нет ПДн и секретов (правило task_135): объект —
  идентификатор, детали — основание человеческими словами.
