# Чек-лист ревью: раздел «Интеграции» (task_145)

Расширение общего чек-листа ревью и чек-листа безопасности
(security/checklist.md) для кода, который ходит наружу или
принимает снаружи. Каждый пункт проверяем глазами по коду
или автоматикой checks_review_q2.py; замечание формулируется
риском («повтор создаст дубль»), а не вкусом («тут некрасиво»).

| № | Пункт | Как проверить |
|---|---|---|
| И-1 | У каждого внешнего вызова явный таймаут по операции | таймаут в конструкторе/политике; сверка с integrations/timeouts.md |
| И-2 | Внешних вызовов внутри транзакции нет | поиском: НачатьТранзакцию и HTTP/WS в одном модуле не соседствуют |
| И-3 | Повторы только на повторяемые ошибки, с политикой и джиттером | классификация §17: 4xx (кроме 429) не повторяются |
| И-4 | Приём идемпотентен: ключ или внешний идентификатор | повтор запроса тестом: duplicate/409, второго документа нет |
| И-5 | Частичный успех обработан явно, а не «пачка упала целиком» | статусы по элементам; очередь недоставленного |
| И-6 | Секреты вне кода; ключи и токены — хешами в базе | сканер секретов; task_134 |
| И-7 | ПДн и payload не попадают в логи; журнал со сквозным ID вызова | санитайзер единой точки; ИдентификаторВызова в записи |
| И-8 | Версия контракта проверяется; изменение схемы сначала ломает тест | OpenAPI version; контрактные эталоны task_140 |
| И-9 | Ошибки партнёра классифицированы: наши 4xx не маскируются под 5xx и наоборот | таблица кодов контура; SEC-2 task_138 |
| И-10 | Деградация при лежащем партнёре определена и видна пользователю | матрица деградации task_131: баннер, отложенные операции |
| И-11 | Предохранитель стоит снаружи повторов, состояние видно мониторингу | порядок вызовов в клиенте; метрика breaker |
| И-12 | Попытки атак и отказы аутентификации пишутся в журнал/аудит | journal auth-записей; события task_137 |

## Ответы на типовые вопросы ревьюера (подготовлены письменно)

1. **Что будет при дубле заказа?** Повтор с тем же external_id
   и ключом идемпотентности — duplicate без второго документа;
   без ключа — честный 409 (task_141, тест живой).
2. **Что при лежащем партнёре?** Предохранитель открывается после
   5 неудач, продажа идёт в режиме деградации с баннером,
   операции ждут в очереди (task_129/131).
3. **Где секрет?** В константах контура/окружении, в базе — хеши;
   сканер в CI зелёный (task_134).
4. **Что в логе при ошибке?** Код RIH, сквозной идентификатор
   вызова, маски вместо ПДн; payload целиком не пишется (task_135).
5. **Какой таймаут и почему?** По операции из timeouts.md
   (лояльность 5 с, ТК 10, банк 5/10/20), а не «по умолчанию».
6. **Что повторится само, а что никогда?** 429/5xx/таймауты —
   с экспонентой и джиттером; 400/401/403/404/409/422 — никогда (§17).
7. **Как узнаем, что партнёр сменил формат?** Canary по расписанию
   раньше ночного обмена; контрактный тест — до релиза (task_140).
8. **Кто останавливал обмен вчера?** Аудит task_137: пользователь,
   время, основание — одной выборкой.
9. **Что произойдёт при 10× нагрузке?** Плато стенда и рост хвоста
   известны (task_143); боевой предел — проведение и лимиты
   партнёров, задачи LOAD-1..4 заведены.
10. **Как откатить плохую настройку интеграции?** По истории
    аудита «было → стало» (task_137), откат — штатное действие.
