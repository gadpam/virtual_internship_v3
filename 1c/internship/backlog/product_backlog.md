# Продуктовый бэклог RIH

Формат записи: **ценность → что делаем → критерий приёмки → размер → приоритет**.
Обновляется раз в спринт (правила — в `README.md`).

## Контур «Магазин»

### B-001 · Приём заказов без участия оператора
* **Ценность:** заказ из онлайн-магазина становится документом 1С за минуты, а не
  к концу дня; оператор не переносит данные руками.
* **Что делаем:** HTTP-сервис приёма заказов, идемпотентность по `externalId`,
  журнал вызовов, очередь при недоступности.
* **Приёмка:** 100 заказов из теста проходят без ручного вмешательства; повтор
  доставки не создаёт дубль; сбой магазина не теряет заказ.
* **Размер:** L · **Приоритет:** P1 · **Задания:** task_83, task_84, task_105

### B-002 · Выгрузка каталога, цен и остатков
* **Ценность:** магазин показывает актуальные цены и наличие; меньше отмен из-за
  отсутствия товара.
* **Что делаем:** инкрементальная выгрузка по `changed_since`, частичный успех,
  отчёт о выгрузке.
* **Приёмка:** 10 000 позиций выгружаются за окно не более 10 минут; отклонённые
  позиции видны в отчёте с причиной.
* **Размер:** L · **Приоритет:** P1 · **Задания:** task_91, task_88

### B-003 · Статусы заказа обратно в магазин
* **Ценность:** покупатель видит реальный статус; меньше обращений в поддержку.
* **Что делаем:** исходящие события `reserved → shipped → delivered → cancelled`.
* **Приёмка:** статус уходит в магазин не позже 5 минут после проведения; при сбое
  магазина событие доставляется повторно.
* **Размер:** M · **Приоритет:** P2 · **Задания:** task_91, task_112

## Контур «Лояльность»

### B-010 · Начисление и списание бонусов
* **Ценность:** клиент получает бонусы сразу; программа лояльности работает.
* **Что делаем:** клиент лояльности с идемпотентностью по `operation_id`, сторно.
* **Приёмка:** начисление ровно один раз при любом числе повторов; сторно возвращает
  баланс; при недоступности сервиса операция уходит в очередь.
* **Размер:** M · **Приоритет:** P1 · **Задания:** task_92, task_130

## Контур «Логистика»

### B-020 · Расчёт и заявка доставки
* **Ценность:** стоимость доставки известна в момент заказа, заявка уходит в ТК
  автоматически.
* **Что делаем:** клиент ТК с соблюдением лимита частоты, компенсация при недоступности
  сервиса этикеток.
* **Приёмка:** расчёт за ≤ 3 с; лимит 10 запросов в минуту не нарушается; заявка не
  теряется при сбое.
* **Размер:** M · **Приоритет:** P1 · **Задания:** task_93, task_130

## Контур «Финансы и банк»

### B-030 · Приём выписки и курсы валют
* **Ценность:** платежи и валютные цены в учёте без ручного ввода.
* **Что делаем:** SOAP-клиент банка, кеш курсов на дату, журнал платёжных поручений.
* **Приёмка:** выписка за день загружается одним прогоном; курсы запрашиваются не
  чаще раза в сутки; платёж не отправляется дважды.
* **Размер:** L · **Приоритет:** P1 · **Задания:** task_86, task_94, task_118

## Контур «Данные и аналитика»

### B-040 · Витрины продаж и интеграций
* **Ценность:** руководитель видит выручку и здоровье интеграций без запросов к
  разработчику.
* **Что делаем:** ETL в PostgreSQL, витрины `fact_sales`, `fact_integration`,
  правила качества, дашборды.
* **Приёмка:** свежесть по SLA (15 минут / T+1 06:00); расхождение с 1С объяснено;
  партия с браком выше 5% блокируется.
* **Размер:** XL → декомпозировать · **Приоритет:** P1 · **Задания:** task_205, task_211, task_212, task_207

### B-041 · Самообслуживание аналитиков
* **Ценность:** аналитик строит отчёт сам, не занимая очередь к разработчику.
* **Что делаем:** песочница с маскированными витринами, лимиты запросов, словарь метрик.
* **Приёмка:** аналитик получил ответ на свой вопрос без участия команды данных;
  персональные данные недоступны; тяжёлый запрос не роняет сервер.
* **Размер:** L · **Приоритет:** P2 · **Задания:** task_209, task_208, task_206

## Контур «Надёжность и эксплуатация»

### B-050 · Алерты и runbooks
* **Ценность:** о сбое узнаёт дежурный, а не клиент.
* **Что делаем:** SLI/SLO, 6 алертов по симптомам, runbook на каждый алерт, дежурство.
* **Приёмка:** учебный сбой обнаружен алертом за ≤ 2 минуты; runbook выполнен
  человеком, который видит его впервые.
* **Размер:** L · **Приоритет:** P0 · **Задания:** task_271, task_272, task_273

### B-051 · Поведение при сбоях партнёров
* **Ценность:** система не лежит вместе с партнёром и не теряет данные.
* **Что делаем:** таймауты, ретраи с джиттером, circuit breaker, DLQ, компенсации.
* **Приёмка:** прогон матрицы сбоев зелёный; после восстановления партнёра операции
  доставлены ровно один раз.
* **Размер:** L · **Приоритет:** P0 · **Задания:** task_127–132

## Контур «AI и мобильность»

### B-060 · Ассистент по базе знаний
* **Ценность:** сотрудник получает ответ по регламенту за секунды вместо поиска по папкам.
* **Что делаем:** корпус знаний, RAG-поиск, цитирование, отказ при низкой уверенности,
  форма в 1С.
* **Приёмка:** hit@5 и MRR не ниже базлайна; на провокационный вопрос — честный отказ;
  ответ содержит ссылку на документ и раздел.
* **Размер:** XL → декомпозировать · **Приоритет:** P2 · **Задания:** task_235–252

### B-061 · Мобильное рабочее место склада
* **Ценность:** приёмка и инвентаризация со сканером, без бумажных листов.
* **Что делаем:** офлайн-данные, синхронизация с разрешением конфликтов, публикация.
* **Приёмка:** работа без сети 2 часа, синхронизация без потери строк, конфликт
  разрешается по правилу, а не «кто первый».
* **Размер:** XL → декомпозировать · **Приоритет:** P3 · **Задания:** task_253–258
