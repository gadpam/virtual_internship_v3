# Бэклог RIH

Здесь живёт список того, что нужно сделать, и список того, что сделано плохо.
Два разных реестра, потому что отвечают они на разные вопросы: **что даём бизнесу**
и **что должны себе**.

| Файл | Что это | Задания |
|---|---|---|
| `product_backlog.md` | продуктовый бэклог: фичи, интеграции, отчёты — с приоритетом и ценностью | task_148, task_180, task_283 |
| `tech_debt_register.md` | реестр технического долга: что сломано, какова цена, в каком порядке чинить | task_220 |
| `refinement_notes.md` | как оцениваем, декомпозируем и принимаем задачи | task_180, task_284 |

## Правила бэклога

1. **Задача формулируется результатом**, а не действием. Не «разобраться с обменом»,
   а «заказ из магазина проводится в 1С без участия оператора».
2. **У каждой задачи есть критерий приёмки** — как понять, что готово. Задача без
   критерия не берётся в спринт.
3. **Приоритет — это порядок**, а не оценка важности. Если «критичных» задач двадцать,
   приоритеты не расставлены.
4. **Размер ограничен спринтом.** Задача больше недели декомпозируется.
5. **Долг не удаляется молча.** Запись уходит из реестра только с указанием, чем
   закрыта: исправлением, принятием риска (с обоснованием) или решением «не чиним».
6. **Бэклог просматривается раз в спринт.** Задача, которая три спринта не нужна,
   закрывается с пометкой «не актуально» — это нормальный результат.

## Оценки

| Оценка | Что означает |
|---|---|
| S | до 2 часов |
| M | 2–6 часов |
| L | 1–2 дня |
| XL | больше 2 дней — обязательно декомпозировать |

Оценка включает: реализацию, тесты, документацию и код-ревью. «Сделаю за час»
без тестов — это не оценка, а оптимизм.

## Приоритеты

| Код | Значение | Правило |
|---|---|---|
| P0 | стоит бизнес-процесс | бросаем текущую работу |
| P1 | деньги, обязательства, данные | в ближайший спринт |
| P2 | неудобство, ручной труд | планируем |
| P3 | улучшение без срочности | когда появится окно |
