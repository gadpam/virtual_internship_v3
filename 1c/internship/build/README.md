# Артефакты стенда (в Git не попадают)

Сюда складывается всё, что **создано**, а не написано: сборки конфигурации,
отчёты тестов, дампы метрик, выгрузки. Каталог намеренно исключён из Git
(`.gitignore` в корне репозитория), кроме этого файла.

Правило простое: если файл можно получить командой из исходников — он артефакт и
лежит здесь. Если его нельзя восстановить — это исходник, и он в Git.

## Структура, которую создаёте вы

| Каталог | Что кладём | Кто создаёт |
|---|---|---|
| `dist/` | `.cf`, `.epf`, `manifest.json` — артефакты релиза | конвейер сборки (task_265) |
| `api/` | экспортированные `openapi.json` для партнёров | task_77 |
| `test-reports/` | `pytest.xml`, отчёты vanessa, скриншоты падений, покрытие | task_66, task_266 |
| `load/` | результаты нагрузочных прогонов: JSON с латентностями и кодами | task_143, task_201 |
| `metrics/` | дампы метрик Prometheus для `report_metrics.py` | task_114, task_271 |
| `export/` | CSV/JSON-выгрузки витрин для партнёров и аналитиков | task_124 |
| `dlq/` | выгрузки сообщений из DLQ для разбора | task_112 |
| `backups/` | локальные копии и протоколы репетиций восстановления | task_193, task_194 |
| `logs/` | логи стенда, выгрузки журнала регистрации | task_61, task_274 |

## Именование

```
<артефакт>_<дата>_<параметры>.<расширение>

load_2026-11-17_target_20rps.json
test-reports_2026-11-17_L3.xml
metrics_2026-11-17_0900-1000.json
export_sales_30d_2026-11-17.csv
```

Дата и параметры в имени обязательны: файл `report.json` через неделю никто не
сможет интерпретировать, а сравнение «до/после» — основа заданий по
производительности (task_192, task_201).

## Команды, которые пишут сюда

```bash
cd 1c/internship

# нагрузочный прогон
python3 src/scripts/generate_load.py --url http://localhost:8080/shop/api/v1/products \
  --header "X-Api-Key:mock-shop-key" --rps 20 --duration 120 \
  --output build/load/load_$(date +%F)_target_20rps.json

# сводка метрик против SLO
python3 src/scripts/report_metrics.py build/load/load_*.json --slo-p95 2.0

# тесты с отчётом для CI
cd tests && pytest -q --junitxml=../build/test-reports/pytest_$(date +%F).xml

# проверка артефактов релиза
cd .. && python3 src/scripts/check_artifacts.py build/dist --manifest build/dist/manifest.json
```

## Чего здесь быть не должно

* секретов, ключей, паролей, `.env` (task_134, task_261);
* персональных данных клиентов в выгрузках (task_135, task_291);
* файлов, которые кто-то собирается коммитить «потом» — артефакт не исходник;
* данных старше 90 дней: архив живёт в `data/` или в резервных копиях, не здесь.

## Очистка

```bash
rm -rf 1c/internship/build/{dist,api,test-reports,load,metrics,export,dlq,logs}
```

Стенд после очистки обязан подниматься и проходить тесты: если что-то сломалось,
значит, в `build/` лежал исходник.
