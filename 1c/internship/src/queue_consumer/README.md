# Консьюмер очереди (Python)

Небольшой сервис, который читает сообщения из RabbitMQ, пишет их в лог и может
повторно доставить в HTTP-сервис 1С. Нужен как «вторая сторона» интеграции в
заданиях task_109–114 (очереди и брокер), task_127–132 (надёжность), task_105 (идемпотентность).

Задача консьюмера — показать правильный паттерн обработки: подтверждение (ack)
только после успешной обработки, отрицательное подтверждение с повторной
доставкой (nack + requeue) для временных ошибок и перевод в «мёртвую» очередь
(DLQ) для постоянных.

## Запуск

```bash
cd 1c/internship/src/queue_consumer
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # укажите AMQP_URL и целевой URL 1С
python3 -m app.main           # консольный режим, Ctrl+C — корректная остановка
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AMQP_URL` | `amqp://guest:guest@localhost:5672/` | подключение к RabbitMQ |
| `QUEUE_NAME` | `rih.orders.in` | очередь на чтение |
| `DLQ_NAME` | `rih.orders.in.dlq` | мёртвая очередь |
| `RIH_HTTP_URL` | `http://localhost:8009/hs/rih/v1/...` | куда передаём сообщение |
| `MAX_RETRIES` | `3` | повторы временной ошибки |
| `PREFETCH` | `10` | глубина предвыборки |

## Поведение при ошибках

| Ответ 1С | Действие консьюмера |
|---|---|
| 2xx | `ack` |
| 408 / 429 / 5xx | `nack(requeue=True)`, счётчик попыток в заголовке `x-retry-count` |
| 4xx (кроме 408/429) | `nack(requeue=False)` → DLQ, причина в логе |
| таймаут/сеть | как 5xx |

Счётчик попыток не даёт сообщению крутиться вечно: при `x-retry-count >= MAX_RETRIES`
сообщение уходит в DLQ — это именно то поведение, которое надо воспроизвести в
очереди 1С в task_110 и task_112.
