# Служебные скрипты стенда

Скрипты, которые обслуживают учебный стенд и используются в заданиях, где надо
«сделать руками то, что потом автоматизируешь»: подготовка данных, генерация
нагрузки, проверка артефактов, восстановление.

Все скрипты — на Python 3.10+, без внешних зависимостей кроме тех, что указаны в
`requirements.txt`. Каждый можно запустить с `--help`.

| Скрипт | Назначение | Задания |
|---|---|---|
| `seed_demo_data.py` | наполняет mock-сервисы учебными данными (товары, заказы, клиенты) | task_73, task_91, task_141 |
| `generate_load.py` | генерирует нагрузку: N запросов с заданным RPS и распределением | task_143, task_200, task_201 |
| `check_artifacts.py` | проверяет целостность артефактов сборки (`.cf`, `.epf`, манифест, контрольные суммы) | task_265, task_266 |
| `restore_from_backup.py` | учебная репетиция восстановления: распаковка, проверка, протокол | task_193, task_194, task_263 |
| `lint_bsl.py` | минимальный линтер модулей 1С по правилам из `Docs/CodingStandard.md` | task_54, task_221 |
| `report_metrics.py` | считает p50/p95/p99 из дампа метрик и печатает таблицу | task_114, task_271 |

## Правила линтера `lint_bsl.py`

Правила — это формализованный `Configuration/Docs/CodingStandard.md`. Если правила
нет в таблице, значит стандарт его не требует: не придумывайте проверки «на всякий случай».

| Код | Серьёзность | Что ловит | Пункт стандарта |
|---|---|---|---|
| R001 | error | `Выполнить()` — динамика, которую нельзя проверить статически | §1 |
| R002 | error | `Сообщить()` вне клиентского контекста (`&НаКлиенте`) | §5 |
| R003 | error | `Перейти ~Метка` | §1 |
| R004 | error | текст запроса инлайн в конструкторе `Новый Запрос("...")` | §3 |
| R005 | error | отступ пробелами вместо табуляции (вне строковых литералов) | §3 |
| R006 | error | символы чужой письменности: иероглифы, кана, хангыль, арабская вязь | §1 |
| R100 | warning | модуль длиннее 1500 строк — нужен план рефакторинга | §2 |
| R101 | info | строка длиннее 140 символов | §2 |
| R102 | warning | метод длиннее 60 строк | §2 |
| R200 | info | экспортный метод без комментария выше | §2 |

Контекст метода определяется по директивам `&НаКлиенте`, `&НаСервере`,
`&НаКлиентеНаСервере`; если директивы нет, код считается серверным (строгая
трактовка — как в общем модуле с вариантом вызова «Сервер»).

```bash
python3 lint_bsl.py ../../Configuration/src                     # текстовый отчёт
python3 lint_bsl.py ../../Configuration/src --format json       # для CI
python3 lint_bsl.py ../../legacy --fail-on warning              # легаси: ловим и предупреждения
```

В L0-конвейере (`tools/ci/github-actions/ci.yml`) линтер запускается с
`--fail-on error`: стартовый код проходит проверку без замечаний, поэтому любое
новое нарушение видно сразу.

## Правила для всех скриптов

1. Ненулевой код возврата при ошибке — чтобы CI мог на нём остановиться.
2. Никаких секретов в аргументах командной строки: только переменные окружения
   или `--config` с файлом вне Git (task_134, task_261).
3. Лог — в stdout, данные — тоже в stdout; отчёты пишутся в `internship/build/`
   (эта папка не попадает в Git).
4. Поддержка `--dry-run` для всего, что что-либо меняет (практика из task_183).
