# ETL: загрузка и качество данных (task_211, task_212, task_213)

**Диалект: PostgreSQL.** Конвейер прайс-листов поставщиков: приём сырых файлов →
проверки качества → нормализация → загрузка в витрину → журнал и отчёт.

| Файл | Шаг конвейера |
|---|---|
| `010_staging_tables.sql` | приёмный слой `staging`: сырые прайс-листы, статусы обменов, инциденты |
| `020_dq_rules.sql` | 15 правил качества данных + таблица результатов |
| `030_load_price_lists.sql` | нормализация и загрузка с идемпотентностью и партией (batch) |
| `040_dedupe_mdm.sql` | поиск дублей НСИ, слияние и отмена слияния (task_213, task_214) |

## Принципы конвейера

1. **Сырой слой не редактируется.** Ошибки исправляются в преобразовании, а сырьё
   остаётся как доказательство: «что нам прислали» и «что мы сделали».
2. **Загрузка партиями с `batch_id`.** Любую партию можно откатить целиком.
3. **Правила качества выполняются ДО загрузки.** Порог: более 5% брака — партия
   отклоняется и уходит инцидентом владельцу данных, а не «доезжает частично».
4. **Идемпотентность.** Повторный прогон той же партии не создаёт дублей
   (`ON CONFLICT`), иначе цифры в BI начнут «плыть».
5. **Журнал на каждый шаг**: сколько пришло, сколько отклонено, почему, за сколько
   секунд. Без журнала разбор инцидента превращается в гадание.

## Прогон

```bash
cd 1c/internship/tools
for f in sql/etl/010_staging_tables.sql sql/etl/020_dq_rules.sql sql/etl/030_load_price_lists.sql; do
  docker compose exec -T postgres psql -U rih -d rih -v ON_ERROR_STOP=1 < "$f"
done
docker compose exec -T postgres psql -U rih -d rih -c "SELECT * FROM staging.v_dq_summary ORDER BY rule_code;"
```
