# Выгрузка данных во внешние форматы (task_124)

Задание: отдать данные наружу — партнёру, аналитикам, в BI, в архив — **контролируемо**.
Контролируемо означает: известно, кто забрал, что именно, в каком объёме, на каком
основании и можно ли это отследить позже.

| Файл | Что делает |
|---|---|
| `030_export_audit.sql` | журнал выгрузок: кто, что, сколько строк, кому передано — **выполнять первым** |
| `010_export_csv.sql` | выгрузка витрины в CSV с разделителем `;` и UTF-8 (для Excel и 1С) |
| `020_export_json.sql` | выгрузка в JSON/JSONB для HTTP-сервисов и очередей |

Порядок выполнения: `030` → `010` → `020` (журнал должен существовать до регистрации выгрузок).

## Правила выгрузки

1. **Формат фиксируется в контракте**, а не «как получилось»: разделитель, кодировка,
   наличие заголовка, формат даты (ISO 8601), десятичный разделитель.
2. **Персональные данные** выгружаются только маскированно
   (`marts.v_sales_masked`) или по письменному основанию — запись в журнале (task_291).
3. **Объём ограничен**: `LIMIT` + фильтр периода. Выгрузка «всей таблицы» — инцидент,
   а не задача.
4. **Каждая выгрузка пишется в журнал** `staging.export_audit`: это ответ на вопрос
   «откуда у партнёра эти данные» через полгода.
5. **Проверка после выгрузки**: число строк и контрольная сумма суммы — сверяются
   с витриной. Расхождение означает, что данные менялись во время выгрузки.

## Пример

```bash
docker compose exec -T postgres psql -U rih -d rih \
  -c "\\copy (SELECT * FROM marts.v_sales_daily WHERE date_key >= CURRENT_DATE - 30) TO '/tmp/sales_30d.csv' WITH (FORMAT csv, HEADER true, DELIMITER ';', ENCODING 'UTF8')"
```

Файл кладите в `internship/build/export/` — каталог не попадает в Git.
