# Диагностика (task_184, task_187, task_204)

Скрипты для ответа на три главных вопроса дежурного: **что происходит сейчас**,
**кто кого блокирует** и **почему запрос медленный**.

| Файл | Вопрос |
|---|---|
| `010_who_is_active.sql` | сессии, ожидания, текущие запросы, план |
| `020_blocking_chain.sql` | цепочки блокировок: кто кого держит |
| `030_query_store_report.sql` | регрессии запросов и анализ планов |
| `040_deadlock_capture.sql` | настройка сбора взаимоблокировок в журнал |

## Порядок расследования «система легла» (task_204)

1. `010_who_is_active.sql` — сколько сессий, какие ожидания преобладают
   (`LCK_M_*` — блокировки, `PAGEIOLATCH_*` — диск, `CXPACKET` — параллелизм,
   `ASYNC_NETWORK_IO` — клиент не забирает результат).
2. `020_blocking_chain.sql` — есть ли голова цепочки блокировок.
3. `030_query_store_report.sql` — не изменился ли план у горячего запроса
   (parameter sniffing, устаревшая статистика).
4. Только потом — решение: снять сессию, обновить статистику, форсировать план.

Фиксируйте таймлайн: время обнаружения, каждая гипотеза, каждая проверка,
что подтвердилось и что нет. Postmortem пишется по этому таймлайну (task_275).
