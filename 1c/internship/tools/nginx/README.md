# nginx: обратный прокси учебного стенда

Единая точка входа: клиент 1С знает один базовый URL
(`http://localhost:8080/`), а nginx распределяет запросы по сервисам.

| Префикс | Сервис | Порт внутри сети |
|---|---|---|
| `/shop/` | онлайн-магазин | 8020 |
| `/loyalty/` | программа лояльности | 8021 |
| `/tk/` | транспортная компания | 8022 |
| `/bank` | SOAP банка | 8023 |
| `/tracker/` | трекер задач | 8024 |
| `/ai/` | AI-сервис (RAG) | 8010 |
| `/metrics` | экспортёр метрик (только внутренняя сеть) | 8025 |
| `/healthz` | агрегированная проверка живости | — |

## Файлы

- `nginx.conf` — основной конфиг: upstream'ы, лимиты, маршруты, формат лога,
  TLS, единый формат ошибки `UPSTREAM_UNAVAILABLE` с `incidentId`.
- `proxy_common.inc` — общие заголовки проксирования, включая проброс
  `X-Correlation-Id` и `X-Request-Id` сквозь всю цепочку.
- `certs/` — самоподписанные сертификаты (генерируются локально, в Git не попадают).

## Что здесь отрабатывается

- **task_93** — лимит частоты: `limit_req_zone` + `burst` + `nodelay`, а также
  корректная передача `429` и `Retry-After` от транспортной компании клиенту.
- **task_133** — минимальная поверхность: `/metrics`, `/docs`, `/redoc` наружу
  закрыты, `server_tokens off`, заголовки `X-Powered-By`/`Server` скрыты.
- **task_274** — сквозная трассировка: формат лога `rih_main` содержит
  `corr=` и `urt=`, по которым разбирают инцидент «заказ не создался».
- **task_262** — три стенда одним конфигом: значения подставляются из `.env`,
  различаются только `NGINX_HTTP_PORT` и именем сети.

## Проверка конфига

```bash
docker compose exec nginx nginx -t          # синтаксис
docker compose exec nginx nginx -s reload   # применить без простоя
curl -si http://localhost:8080/healthz
curl -si http://localhost:8080/shop/health
curl -si http://localhost:8080/metrics      # ожидаем 403 извне внутренней сети
```
