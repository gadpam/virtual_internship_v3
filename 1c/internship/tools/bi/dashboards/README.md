# Дашборды RIH (task_207)

Три дашборда — по числу ролей, которые принимают решения: коммерция, инженерия,
данные. Каждый дашборд начинается с **баннера свежести**: пользователь обязан
видеть, на какое состояние данных он смотрит.

| Дашборд | Зритель | Главный вопрос |
|---|---|---|
| `01_sales_daily.md` | коммерческий директор, аналитик розницы | где выручка проседает и почему |
| `02_integration_health.md` | дежурный инженер, владелец интеграции | всё ли обменивается и в какой срок |
| `03_data_quality.md` | владелец данных НСИ, инженер данных | можно ли верить цифрам |

## Общие правила оформления

1. **Один дашборд — один вопрос.** Если на панели нельзя сказать, какое решение
   по ней принимают, панель лишняя.
2. **Сверху — вывод, снизу — детали.** Первая строка: KPI и отклонение от плана.
   Детализация — ниже, drill-down по клику.
3. **Свежесть видна всегда** (`marts.v_freshness`): дата последнего обновления
   и статус SLA.
4. **Единые цвета и единицы**: BYN, %, секунды — из словаря метрик, без «своей»
   трактовки на дашборде.
5. **Фильтры — в шапке**: период, магазин/город, канал, система-партнёр.
6. **Не более 9 панелей** на дашборд; больше — значит, нужен второй дашборд.
