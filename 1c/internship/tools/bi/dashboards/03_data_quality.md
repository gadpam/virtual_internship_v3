# Дашборд «Качество данных»

**Зритель:** владелец данных НСИ, инженер данных, руководитель разработки.
**Вопрос:** можно ли верить цифрам в отчётах и дашбордах, где именно брак и кто
его исправляет.
**Источники:** `staging.v_dq_summary`, `marts.etl_runs`, `marts.v_freshness`,
`marts.v_sales_anomalies`, `staging.mdm_merge_log`.

## Панели

| № | Панель | Тип | Что показывает | Порог |
|---|---|---|---|---|
| 0 | Свежесть витрин | Table | `marts.v_freshness` — SLA по каждой витрине | нарушение → красный |
| 1 | Доля брака в последней партии | Big Number | M-009 | 5% — блокировка загрузки |
| 2 | Нарушения по правилам DQ | Bar chart | `rows_failed` по `rule_code` (15 правил) | block-правило > 0 |
| 3 | Тренд качества за 30 дней | Time-series | M-009 по дням и источникам | рост → разбор |
| 4 | Прогоны ETL | Table | `marts.v_etl_runs_24h`: статус, длительность, строки | `failed` — инцидент |
| 5 | Дубли НСИ | Big Number + Table | кандидаты из `staging.v_product_duplicate_candidates` | — |
| 6 | Слияния и отмены | Table | `staging.mdm_merge_log` (активные/отменённые) | отмена > 10% — ревизия правил |
| 7 | Аномалии продаж | Table | `marts.v_sales_anomalies` (>2 SD) | — |
| 8 | Ответственные за правила | Table | `owner_role` по числу нарушений | — |

## Правило порога 5%

Если block-правила нарушены хотя бы в одной строке или warn-правила превысили
порог, партия **не грузится** в витрину, а уходит инцидентом владельцу данных.
Частичная загрузка хуже полной остановки: цифра на дашборде выглядит правдоподобно,
но не совпадает с учётом, и доверие к BI теряется навсегда.

## Drill-down

Клик по правилу (панель 2) → список строк-нарушителей с `batch_id` и `row_no`,
чтобы написать поставщику конкретное письмо: «в файле X строка 142, цена не число».

## Проверка приёмки

1. Загружена учебная партия с 3 намеренными ошибками (пустой артикул, цена
   текстом, неизвестный поставщик) → панель 2 показывает три нарушения, партия
   отклонена, в `marts.etl_runs` запись `status = 'failed'`.
2. Панель 0 показывает нарушение SLA, если витрина не обновлялась сутки.
3. Все панели имеют владельца: у каждой — имя роли, а не «команда данных».
