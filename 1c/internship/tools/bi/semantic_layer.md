# Семантический слой BI (task_206)

Семантический слой — это договор о том, **что означает каждая цифра**. В стенде RIH
он физически существует как таблица `marts.metrics_dictionary` + представления
витрин. Дашборд не имеет права считать метрику «сам».

## Структура слоя

```
источники 1С и партнёров
        ↓ (выгрузка, task_124)
staging — сырой слой, без исправлений
        ↓ (правила качества DQ-01..DQ-15, task_212)
marts — витрины: dim_* и fact_*, согласованные формулы
        ↓ (представления v_*)
BI: Superset, Grafana, отчёты 1С
```

## Состав словаря метрик

10 метрик (M-001…M-010) с полями: код, название, определение, формула SQL,
источник, единица, детализация, владелец, SLA свежести, признак конфиденциальности,
статус, дата утверждения, примечание.

Полный список — `tools/sql/marts/040_metrics_dictionary.sql`;
читаемое представление — `marts.v_metrics_dictionary`.

## Измерения

| Измерение | Таблица | Иерархия |
|---|---|---|
| Дата | `marts.dim_date` | год → квартал → месяц → неделя ISO → день |
| Магазин | `marts.dim_store` | город → формат → магазин |
| Товар | `marts.dim_product` | категория → бренд → SKU |
| Контрагент | `marts.dim_counterparty` | вид → контрагент |
| Поставщик | `staging.dim_supplier` | поставщик |
| Система | `marts.fact_integration.system_code` | система → операция → направление |

## Жизненный цикл метрики

1. **Запрос.** Бизнес формулирует вопрос, а не «сделайте отчёт».
2. **Черновик** (`status = 'draft'`): определение, формула, источник, владелец.
3. **Согласование.** Владелец метрики и потребитель подтверждают, что формула
   соответствует вопросу. Расхождения с учётом фиксируются в `notes`.
4. **Утверждение** (`status = 'active'`, `approved_at`): метрику можно выносить
   на дашборд.
5. **Устаревание** (`status = 'deprecated'`): метрика не удаляется из словаря —
   иначе старые дашборды теряют объяснение. Указывается замена.

## Типичные конфликты и как их решать

| Конфликт | Причина | Решение |
|---|---|---|
| Выручка в BI ≠ выручка в БП | разный момент признания (факт продажи vs отгрузка и закрытие периода) | две метрики с явными определениями и примечанием о расхождении |
| Себестоимость «поехала» задним числом | пересчёт при закрытии месяца | в `notes` указываем изменчивость, в дашборде — дата актуальности |
| Средний чек спорят два отдела | считают по строкам и по чекам | M-004 в статусе `draft`, вводим отдельную метрику по `doc_number` |
| Одна метрика в трёх дашбордах с разными цифрами | формулу переписали в панели | выносим расчёт в представление витрины, панель только читает |

## Правило для стажёра

Если вас просят «просто добавить цифру» — сначала запись в словарь. Пять минут
на определение экономят часы споров о том, почему цифры расходятся.
