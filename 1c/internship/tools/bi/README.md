# BI-трек (спринт 35: task_205–210)

Инструмент — Apache Superset поверх PostgreSQL (витрины из `tools/sql/marts/`).
Выбор объясняется просто: бесплатно, работает в контейнере, умеет RLS и словари.
В вакансиях встречаются Tableau, Power BI, Qlik — принципы те же, отличается
синтаксис построения дашборда, поэтому перенос навыка занимает дни, а не месяцы.

## Как устроен BI-трек

1. **Витрины** (`tools/sql/marts/`) — единственный источник. BI не читает регистры
   1С напрямую: иначе каждый дашборд превращается в тяжёлый запрос к рабочей базе.
2. **Семантический слой** — словарь метрик `marts.metrics_dictionary`: формула,
   единица, детализация, владелец, SLA. Новая цифра на дашборде появляется только
   после записи в словарь.
3. **Дашборды** — три: продажи, здоровье интеграций, качество данных. Каждый
   отвечает на вопрос конкретной роли.
4. **Доступы** — роли, RLS по городу/магазину, маскирование ПДн, песочница для
   аналитиков, где нельзя сломать витрины.
5. **SLA свежести** — без него дашборд врёт уверенно: пользователь видит цифру и
   не знает, что она вчерашняя.

## Проверка стенда

```bash
cd 1c/internship/tools
docker compose -f docker-compose.full.yml up -d postgres superset
# http://localhost:8088 (admin / SUPERSET_SECRET_KEY из .env)
docker compose exec -T postgres psql -U rih -d rih -c "SELECT * FROM marts.v_freshness;"
docker compose exec -T postgres psql -U rih -d rih -c "SELECT * FROM marts.v_metrics_dictionary;"
docker compose exec -T postgres psql -U rih -d rih -c "SELECT * FROM staging.v_dq_summary;"
```

## Приёмка BI-заданий

Задание считается выполненным, если:

- дашборд открывается за заданное время и не содержит «самодельных» формул в панелях;
- баннер свежести показывает реальное состояние витрины;
- RLS проверен под тестовой ролью (чужие строки не видны вовсе);
- цифры сверены с отчётом 1С, расхождение объяснено и зафиксировано в словаре;
- есть письменная спецификация панелей (файлы в `dashboards/`) — по ней дашборд
  может собрать другой человек.
