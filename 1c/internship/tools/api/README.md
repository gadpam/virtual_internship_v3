# Коллекции API: Postman / Bruno

Исполняемая документация контрактов RIH и партнёров. Коллекция из этого
каталога обязана работать против стенда одной кнопкой: поднял стенд —
запустил — зелёно.

## Что здесь живёт

| Файл | Что это | Задание |
|---|---|---|
| `rih_partners.postman_collection.json` | коллекция Postman по API магазина (сценарий «каталог → заказ») | task_74, task_76 |
| `environments/*.postman_environment.json` | окружения Postman: local / dev / test | task_76 |
| `bruno/` | та же коллекция в формате Bruno (если команда выбрала Bruno) | task_76 |

## Переменные окружения

- `baseUrl` — адрес стенда, например `http://localhost:8020` (mock_shop_api);
- `apiKey` — ключ API; значение только в локальном окружении и `.env`,
  **в репозиторий секрет не коммитится**;
- `period` — период выборок для сценариев с датами.

В коллекции — только имена переменных (`{{baseUrl}}`), не значения секретов.

## Запуск проверок

```bash
# Postman CLI (newman)
newman run rih_partners.postman_collection.json \
  -e environments/local.postman_environment.json

# Bruno CLI
bru run bruno/ --env local
```

Проверки (tests) стоят на каждом запросе: код ответа, обязательные поля,
схема ответа. Коллекция без негативных запросов (битые данные → ожидаемый
4xx) проверяет только то, что сервер включён.

## Правило синхронизации

Изменился контракт (task_77, task_83) — в том же коммите обновилась
коллекция и её проверки. Коллекция, отставшая от сервиса, хуже
отсутствующей: ей верят.
