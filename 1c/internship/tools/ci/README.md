# CI для сценариев 1С (task_53)

## Честный статус

Платформа 1С в CI недоступна (лицензии и дистрибутив не могут лежать
в публичном раннере). Поэтому сценарии vanessa (`internship/tests/features/`)
в CI **не запускаются**, а шаг фиксируется пропуском с причиной — не
красной ложью и не зелёной. Локальный прогон: vanessa-runner на стенде
с платформой; до её появления числа сценариев исполняет зеркальный
раннер `src/scripts/run_all_checks.py` (checks_posting/checks_stock_control
покрывают приёмочный и негативный сценарии цифрами).

## Как включить, когда платформа появится

1. Раннер с EDT/платформой и лицензией (self-hosted).
2. Шаг: собрать конфигурацию из исходников, развернуть тестовую ИБ,
   прогнать `vanessa-runner run` по `tests/features/`.
3. Отчёт прогона (junit) приложить к запуску; падение сценария = красный шаг.

## Что гоняется в CI уже сейчас

- Линтер BSL и проверки исходников (task_12) — без платформы.
- Зеркальные проверки (run_all_checks.py) — алгоритмы и SQL-аналоги.

## Разбор workflow по шагам (task_64)

Реальный конвейер репозитория — `.github/workflows/validate.yml`
(«Validate program», запускается на push и pull_request):

| Шаг | Что делает | Блокирует merge |
|---|---|---|
| checkout + setup-python | Исходники и Python 3.12 | — |
| Валидатор программы | py_compile, ссылки теории, часы, идемпотентность генерации | Да |
| Линтер модулей 1С | lint_bsl по Configuration/src, `--fail-on warning` | Да |
| AI-сервис: зависимости + pytest | Тесты смежного Python-сервиса стенда | Да |

Учебный образец полного конвейера для своего форка лежит рядом
(`tools/ci/github-actions/ci.yml`, уровни L0–L3): линт → модульные →
контрактные → интеграционные; изучается в task_265/266.

## Сборка .cf и дымовые тесты: честный статус

Сборка Rih.cf из исходников EDT в CI **не выполняется**: нужны EDT
и лицензия платформы, которых у публичного раннера нет. Сборка остаётся
локальной на стенде с платформой; CI вместо неё валидирует исходники
(линтер + целостность XML), то есть ловит те же классы ошибок раньше.
Шаг публикации артефакта Rih.cf добавляется вместе с self-hosted
раннером из раздела выше; публиковать «как бы .cf» из исходников без
сборки — недопустимая подмена артефакта. Дымовые сценарии vanessa —
та же история: в CI помечены пропуском с причиной (task_53), числа
сценариев исполняет зеркальный раннер локально.

## Branch protection (правило, настраивается на форке)

PR не сливается при красном «Validate program»: обязательные проверки —
валидатор и линтер; прямое обновление main запрещено, merge только
через PR с зелёными обязательными шагами. Причина правила: красный CI,
который можно обойти кнопкой, перестаёт быть сигналом (урок task_53).
