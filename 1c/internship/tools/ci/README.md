## Уровни тестов в CI (task_266)

| Уровень | Что запускается | Когда | Бюджет времени |
|---|---|---|---|
| L0 | линт `.bsl`, проверка стандарта, синтаксис | каждый push | < 2 мин |
| L1 | модульные тесты 1С и Python | каждый push | < 5 мин |
| L2 | контрактные тесты (mock-сервисы) | каждый push в PR | < 10 мин |
| L3 | интеграционные + e2e (vanessa) | merge в main, ночной прогон | < 30 мин |
| L4 | нагрузочные и дымовой прогон отчётов | перед релизом, по расписанию | < 60 мин |

Правило: L0–L2 блокируют merge, L3 блокирует релиз, L4 даёт данные для решения
о релизе, но не останавливает его автоматически — решение принимает владелец
релиза по критериям из `../../project/documentation/ReleasePlanTemplate.md`.

## Локальный прогон

Перед push прогоняйте то же, что сделает CI:

```bash
cd 1c/internship
python3 tools/../src/scripts/lint_bsl.py Configuration/src --fail-on error
cd src/ai_service && python3 -m pytest -q
cd ../../tests && python3 -m pytest -q contract
```

## Почему CI важен именно в 1С

1С-разработчик привыкает к «проверил руками в предприятии». На стенде с тремя
окружениями, интеграциями и релиз-поездами это не масштабируется: ручная проверка
не воспроизводится, а регресс находится пользователем. Текстовые исходники EDT +
CI — то, что делает 1С-разработку инженерной практикой (это прямо требуется в
вакансии: «знание стандартов разработки 1С», работа с Git и CI).
