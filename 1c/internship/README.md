# internship/ — рабочая папка трека 1С

Здесь вы работаете: пишете код, тесты, документацию и артефакты. Программа
стажировки (задания) живёт в `1c/project/` и **не меняется**; всё, что вы создаёте,
появляется здесь.

Проект, который вы строите год: **Retail Integration Hub (RIH)** — конфигурация
1С 8.3, которая связывает онлайн-магазин, программу лояльности, транспортную
компанию, банк, бухгалтерию, документооборот и BI в один управляемый контур.

## С чего начать

1. Прочитать `1c/README.md` — легенда, правила, как устроена программа.
2. Открыть `1c/project/sprint_0/task_0/YourTask.txt` — первое задание.
3. Поднять стенд: `tools/README.md` → `docker compose up -d --wait`.
4. Завести привычку: после каждого задания — `documentation/task_NNN_description.txt`
   и `documentation/reflections/task_NNN_reflection.md`.
5. Перед заданием смотреть [`documentation/ArtifactMap.md`](documentation/ArtifactMap.md):
   что уже есть в стенде, а что вы создаёте этим заданием и куда кладёте результат.

## Как устроен стенд

Точка входа одна — nginx на порту **8080** (HTTP) и **8443** (HTTPS). Остальные
сервисы живут во внутренней сети и наружу не публикуются.

| Сервис | Порт внутри сети | Путь через nginx | Назначение |
|---|---|---|---|
| nginx | 8080, 8443 | — | единая точка входа, TLS, лимиты, журналы |
| 1С (RIH) | 8009 | `/rih/` | HTTP-сервисы конфигурации |
| `ai_service` | 8010 | `/ai/` | RAG-поиск и ответы по базе знаний |
| `mock_shop_api` | 8020 | `/shop/` | онлайн-магазин |
| `mock_loyalty_api` | 8021 | `/loyalty/` | программа лояльности |
| `mock_tk_api` | 8022 | `/tk/` | транспортная компания |
| `mock_bank_ws` | 8023 | `/bank` | банк, SOAP |
| `mock_tracker_api` | 8024 | `/tracker/` | внешний трекер задач |
| `metrics_exporter` | 8025 | `/metrics` | метрики Prometheus |
| RabbitMQ | 5672, 15672 | — | очереди и DLQ |
| PostgreSQL | 5432 | — | витрины, ETL, pgvector |
| Prometheus / Alertmanager | 9090 / 9093 | — | метрики и алерты |
| Grafana | 3000 | — | дашборды SLO |
| Superset | 8088 | — | BI-контур |

Три compose-файла: `docker-compose.yml` (базовый стенд), `docker-compose.test.yml`
(для тестов), `docker-compose.full.yml` (15 сервисов — сквозной сценарий года).

## Уровень тестов и где он живёт

| Уровень | Каталог | Что проверяет | Блокирует |
|---|---|---|---|
| L0 | линтер `.bsl`, скан секретов | стандарт кодирования | merge |
| L1 | `tests/unit/`, `src/ai_service/tests/` | функции и модули | merge |
| L2 | `tests/contract/` | контракты партнёров | merge |
| L3 | `tests/integration/`, `tests/e2e/`, `tests/features/` | цепочки и сценарии | релиз |
| L4 | `tests/load/`, `tests/golden_path/` | нагрузка и золотой путь | информирует владельца релиза |

Запуск: `cd tests && pytest -q -m unit` (маркеры — в `tests/pytest.ini`).

## Правила работы в этой папке

1. **`1c/project/` не меняется.** Это программа и критерии; править их — значит
   потерять ориентир.
2. **Секретов в Git нет.** Значения — в `.env` (шаблон: `tools/.env.example`).
3. **Артефакты — в `build/`.** Бинарные `.cf`/`.epf` в репозиторий не кладутся.
4. **Каждое изменение контракта** идёт вместе с обновлением `docs/api/` и
   контрактного теста.
5. **Каждое решение с альтернативами** — в `documentation/adr/`.
6. **Каждое задание** — с описанием и рефлексией в `documentation/`.
7. **Код проходит ревью.** До merge: L0–L2 зелёные, замечания закрыты.
